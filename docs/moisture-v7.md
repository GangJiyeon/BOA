# BOA 자동 뺨 수분 측정 v7

이 패치는 기존 moisture_sensor, 피부 분석 화면, 결과 화면, 백엔드를 함께 수정합니다.
표시값은 공기 기준 대비 상대 신호 변화율이며 절대 피부 수분 함량이나 임상 판정값이 아닙니다.

## 적용 순서

1. 기존 프로젝트를 백업하세요. ZIP의 backend / frontend / hardware / docs 폴더를
   C:\Users\USER\Desktop\BOA-git에 합쳐 덮어쓰세요. 프로젝트의 나머지 파일은 삭제하지 않습니다.
2. Docker Desktop과 기존 DB를 켜고 PowerShell에서 실행하세요.

```powershell
cd C:\Users\USER\Desktop\BOA-git\backend
docker compose up -d
docker compose exec api python scripts/upgrade_moisture_v7.py
```

스크립트는 DB가 ae596f5070ae일 때만 f0810a1b2c3d로 갱신합니다. 이미 v7이면 재실행해도 됩니다.
그 외 버전이면 DB를 변경하지 않고 현재 버전을 출력합니다. 그 출력을 공유하세요.
기존 계정 마이그레이션에는 legacy 테이블 삭제가 있어 여기서 일괄 upgrade head를 권하지 않습니다.
임의로 stamp하거나 기존 마이그레이션을 삭제/수정하지 마세요.
이번 마이그레이션 자체는 moisture_observations 테이블 하나만 추가하며 기존 점수를 수정하지 않습니다.
로컬 Python 백엔드 사용자는 해당 가상환경에서 python scripts/upgrade_moisture_v7.py를 실행합니다.

3. hardware/arduino/moisture_sensor/moisture_sensor.ino를 열어
   UNO R4 WiFi / COM5로 한 번 업로드하세요. ArduinoBLE 라이브러리가 필요합니다.
   같은 폴더의 헤더도 자동 포함됩니다. tests 폴더는 업로드 대상이 아닙니다.
4. 프론트를 실행합니다. 새 npm 의존성은 없습니다.

```powershell
cd C:\Users\USER\Desktop\BOA-git\frontend
npm run dev
```

5. Chrome/Edge의 localhost에서 피부 분석 화면을 엽니다. 기존 BLE 연결을 종료하고 재연결합니다.
   자동 측정은 v7 펌웨어가 필요합니다. 새 특성이 보이지 않으면 브라우저의 장치 권한을 제거하고 다시 연결하세요.

## 첫 사용

권장 순서: 얼굴 사진 선택·분석 완료 → 측정기 연결 → 기준값 보정 → 왼쪽 뺨 접촉.

- 손을 센서에서 떼고 '기준값 보정'을 누릅니다.
- 3초 준비 + 약 2초 보정 표본 수집 + 2초 공기 잡음 확인 후 '왼쪽 뺨에 대세요' 안내를 기다립니다.
- 정한 왼쪽 뺨 위치에 센서의 감지면을 평평하게 대고 유지합니다.
- 접촉 변화 확인, 약 1초 안정화 후 3초간 수집합니다. 전체 접촉은 최소 약 4.3초입니다.
- 유효한 측정이 끝나면 자동 결과와 완료음(브라우저가 허용하는 경우)이 나오고 분석에 저장합니다.
- 계속 접촉해도 재저장하지 않습니다. 뗀 상태가 1초 확인된 뒤 다음 측정을 허용합니다.
- 손으로 누르는 힘을 수치가 커질 때까지 증가시키지 마세요. 힘은 현재 하드웨어로 측정/보정하지 않습니다.
- 손잡이·케이스로 감지면의 접촉 위치와 면적을 일정하게 만드는 것이 후속 하드웨어 과제입니다.
  얼굴에는 감지면만 닿도록 하며 핀·기판 모서리를 피부에 대지 않습니다.

사진 분석 전에 측정해도 같은 사진/입력 문맥의 분석이 생성되면 자동 저장합니다.
사진·입력 모드·수동 수분 점수를 바꾸면 진행 중 측정과 미연결 결과를 초기화합니다.
분석 ID가 측정 도중 바뀌면 진행 구간을 취소하고 공기 상태부터 다시 확인합니다.
이미 특정 분석에 연결한 결과는 다른 분석에 재사용하지 않습니다.
화면을 떠나면 진행 중 측정과 BLE 연결을 종료합니다. 이미 서버에서 완료된 저장은 취소되지 않습니다.
사진 분석 없이 화면을 종료/새로고침하면 아직 서버에 연결하지 않은 결과는 유실됩니다.

## 결과의 의미와 저장

- 상대 지표 = max(0, 기준값 - 측정 평균) / 기준값 * 100. 결과는 소수 둘째 자리까지 표시.
- 수분 항목 및 결과 모아보기에서 측정 완료 상대 지표를 표시합니다.
- 원시 표본, 순번, 장치 시간, 기준값, 측정 부위(left_cheek), 완료 시각,
  알고리즘 버전, 접촉/해제 기준, 평균·표준편차·범위를 DB에 보존합니다.
- POST /api/skin/moisture/results는 같은 measurement_id의 같은 요청을 재전송해도 한 번만 저장합니다.
  같은 ID를 다른 분석이나 다른 내용에 재사용하면 409입니다.
- 서버는 표본 수·간격·변동을 검증하고 평균/상대 지표를 직접 다시 계산합니다.
- GET /api/skin/analyses/{id}의 moisture_measurement로 최근 완료 결과를 조회합니다.
  늦게 저장된 과거 측정이 최근 측정을 덮지 않도록 완료 시각으로 선택합니다.
- 서버 저장 실패 시 측정 결과는 화면에 남고 '같은 결과 저장 재시도'를 제공합니다.
- 기존 SkinScore와 추천 점수는 수정하지 않습니다. 상대 %를 ADC 변환 경로(0~1023)나
  수동 점수에 넣지 않습니다. 수동 수분 점수가 따로 있었다면 추천에는 그 점수가 남아 있음을 표시합니다.
- 백엔드는 기존 분석 API와 동일한 접근 정책을 사용합니다. 이 패치는 별도 사용자 소유권 체계를 추가하지 않습니다.
- 상세 영역의 '이번 측정 실험 데이터 내려받기'로 원시 표본과 조건을 JSON으로 보관할 수 있습니다.

## 상태와 기본 실험 설정

상태 책임: 프론트의 AutoMeasurement가 접촉 대기/안정화/수집/완료를 결정합니다.
펌웨어는 센서 초기화, 공기 보정, 변환 완료 확인 및 경고 전달만 담당합니다.

미연결 → 보정 필요 → 보정 중 → 공기 잡음 확인 → 접촉 대기 → 접촉 후보
→ 안정화 → 3초 수집 → 완료 → 접촉 해제 대기 → 다음 측정.
중간 경고/이탈/불안정/지연/표본 부족은 해당 구간 전체 취소. 제한 시간 초과도 실패입니다.

실험용 설정은 frontend/src/moisture/autoMeasurement.ts의 AUTO_CONFIG에 모았습니다.
서버 검증 규칙은 backend/app/schemas/moisture.py에 있으며 변경 시 양쪽 규칙과 버전을 함께 갱신합니다.
이 숫자는 피부 임상 표준이 아닙니다.

- 새 표본 수집 시도: 100ms마다, TI STATUS bit 3(CH0_UNREADCONV) 확인 후 DATA를 한 번만 읽음.
- 보정: 20개 새 표본, 0/경고 거부, 표본 범위가 max(4 count, 기준값 약 2%) 초과면 실패.
- 공기 확인: 2초 및 최소 16개 표본. 기준값 대비 ±2%에서 벗어나면 확인 구간 재시작.
- 접촉 기준: max(2%, 공기 변화 평균 절댓값 + 공기 표준편차 × 6).
- 해제 기준: 접촉 기준의 절반. 작은 반응을 놓칠 수 있어 뺨 데이터로 검토해야 합니다.
- 접촉 후보 확인: 300ms. 안정화: 1초 및 최소 8개 표본, 범위 3%p 이내.
- 수집: 3초 및 최소 25개 새 표본. 범위 3%p, 표준편차 1.2%p 이내.
- 구간 내 350ms 초과 간격, 경고, 접촉 해제는 취소. 수신이 750ms 끊겨도 취소.
- 장치 시간만 빠르게 진행되는 버퍼 표본으로 순식간에 측정을 완료하지 않도록 실제 수신 경과시간도 확인.
- 접촉 후보부터 10초 내 완료하지 못하면 실패. 재시작은 해제 1초 확인 후.
- 중복 패킷은 타이머를 진행시키지 않음. 카운터의 정상 순환은 허용하고 역행/재시작은 재보정 요구.

압력을 일정하게 유지했더라도 강한 압력으로 생긴 편향은 이 안정성 검사로 검출할 수 없습니다.
건조한 피부와 작은 접촉 면적, 근접 반응을 신호만으로 완전히 구분할 수 없습니다.

## 실물 실험: 다음 단계

1. 같은 사람·같은 왼쪽 뺨 위치·같은 센서 방향으로 뗐다 대기를 5회 실시.
2. 각 완료 결과 JSON을 보관하고 완료율, 상대 지표 범위, 실패 사유를 기록.
3. 짧게 대고 떼기, 접촉 중 위치 이동, 연결 종료에서 결과가 생성되지 않는지 확인.
4. 계속 접촉해도 저장은 1회이고, 충분히 뗀 뒤 다음 결과만 생성되는지 확인.
5. 결과가 분석 수분 칸과 결과 조회에 같은 값으로 남는지 확인.
6. 낮은 반응이나 보통 접촉에서도 실패가 잦으면 로그로 기준을 조정합니다.
   실패를 없애려고 경고를 무시하거나 압력을 세게 가하는 방법으로 맞추지 않습니다.

실측 반복성이 확보되기 전에는 건조/보통/높음 경계를 정하지 않습니다.
절대 정확도 검증에는 같은 부위의 기준 측정기와 비교한 별도 데이터가 필요합니다.

  I2C 복구, BLE v1/v2/v3 패킷.
- 프론트 production build 및 BLE 프로토콜 테스트 통과.
- 자동 상태 테스트: 정상, 유지 중 중복 방지, 해제 후 재측정, 짧은/작은/불안정 접촉,
  경고, 지연, 중복, 버퍼 재생, 순번/시간 순환, 재부팅, 기준값/문맥 변경.
- React DOM 조작 모사: 보정 버튼→자동 완료, 종료, 분석 전 완료 후 연결,
  고정 분석 ID로 재시도, 문맥 변경 및 늦은 응답 무시.
- 서버 수분/마이그레이션 테스트 10개 + 기존 피부 연동 13개 + 화장품 회귀 30개 통과.
- PostgreSQL 마이그레이션 SQL 생성 확인 및 SQLite에서 버전 가드/새 테이블/재실행 확인.
- 실제 뺨 접촉, 실제 Windows BLE 품질, 브라우저 시각 렌더링, 실제 PostgreSQL 적용은 사용자 환경에서 확인해야 합니다.

## 통신 및 출처

기존 BLE 서비스 98b10000-e8f2-537e-4f6c-d104768a1214 유지.
0001의 v1과 0002의 v2를 유지하며 0004에 v3(20 bytes)를 추가했습니다.
v3 배치는 v2와 같고, 정상 값이 한 번의 새 변환이라는 의미를 명시합니다.
프론트는 0004 → 0002 → 0001 순으로 연결하지만 자동 측정은 v3만 허용합니다.
보정 명령은 기존 0003에 byte 1을 쓰는 방식입니다. 상세 v2 배치는 이전 v6 문서를 참고하세요.

- 제조사 참고 초기 설정/상대 계산: https://github.com/MikroElektronika/Moisture_click
- FDC2112 변환 완료 확인: https://www.ti.com/lit/ds/symlink/fdc2112.pdf
- 원본 라이선스: hardware/arduino/moisture_sensor/NOTICE.txt
- 부위 차이 연구: https://pmc.ncbi.nlm.nih.gov/articles/PMC6850423/
- 압력 영향 연구: https://pubmed.ncbi.nlm.nih.gov/21338409/

Git 커밋/푸시 및 실제 DB 변경은 이 작업 환경에서 수행하지 않았습니다.
