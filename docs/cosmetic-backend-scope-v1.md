# 얼굴 화장품 추천 후보 범위 보완

2026-10-05 / 엔진 `cosmetic-preview-v3.2`

## 실제 확인한 문제

업로드된 원본 SQLite와 통합 ERD, 백엔드 후보 필터를 읽었다. ERD의 PRODUCT는 카테고리와 전성분 등을 가지지만 사용 부위 필드가 없다. 기존 엔진은 moisturizer/serum/toner와 normalized 상태를 통과하면, 워시오프·필링 등의 일부 이름만 검사했다. 따라서 바디로션과 눈가용 아이크림도 얼굴 지표 추천에 들어갈 수 있었다.

- `A000000246674`: [저자극 바디로션] 오브제 맥스 올인원 로션 500ml — moisturizer, normalized
- `A000000200168`: 토리든 셀메이징 저분자 콜라겐 탄력 아이크림 30ml — moisturizer, normalized
- `A000000161776`, `A000000161777`: 페이스워시가 포함된 우르오스 기획 — 사용 방식 분류 누락. 현재는 review 상태여서 기존에도 다른 필터로 제외되지만 추후 정규화되어도 잘못 통과하지 않도록 보완했다.

카테고리와 전성분 정규화 상태는 얼굴 전체에 쓰는 제품이라는 검증이 아니다.

## 적용 정책

기존 API 계약의 `uncertain`과 `excluded_by_usage`를 사용한다. 새 DB 필드나 성분 효능 태그는 추가하지 않는다.

| 제품명 단서 | 처리 |
|---|---|
| 바디로션·바디크림 등 | 얼굴 사용 범위 미확인으로 보류 |
| 손·발·입술·두피·모발용 유형 | 얼굴 사용 범위 미확인으로 보류 |
| 아이크림·아이세럼·아이밤 | 얼굴 전체 지표 추천 범위 미확인으로 보류 |
| 페이스&바디크림 | 기존처럼 추정 후보 허용 |
| 아이크림 포 페이스 | 기존처럼 추정 후보 허용 |
| 눈가용 증정품 포함 | 성분표 소유 제품과 적용 범위 확인 전 보류 |
| 페이스워시·세안·샴푸 등 | 씻어냄, 혼합 구성은 불명확으로 분류 |
| 더바디샵·헤어핀·핸드타올 | 해당 단어만으로 사용 부위를 배제하지 않음 |

NFKC 및 대소문자·공백 정규화 후 단서를 확인한다. 이름이 없으면 사용 방식을 추정하지 않는다. 페이스 표기가 있더라도 씻어내는 제품이나 손 전용 구성품 등의 단서를 무시하지 않는다.

이것은 **제품명 기반의 후보 범위 정책**이다. 눈가용 제품의 얼굴 사용이 위험하다거나, 바디 제품은 얼굴에 절대로 쓸 수 없다는 의학적 판정이 아니다. 제조사 사용법을 조회한 결과도 아니다. 이름에 단서가 없으면 아직 추정 후보로 남을 수 있고, 이름에 증정품이 포함되어 정상 본품까지 보류될 수 있다. 장기적으로 검증된 사용 부위·방식 및 구성품과 성분표의 대응이 필요하다.

## 원본 데이터 영향

원본 2,584개 제품의 사용 분류 중 61개가 변경됐다. 이 중에는 기존 카테고리·정규화 필터에서 이미 제외되던 제품도 있으므로 61개를 모두 새 추천 제외 제품으로 세지 않는다.

| 개발용 입력 사례 | 이전 후보 | 수정 후 후보 |
|---|---:|---:|
| 수분 단독 | 1,648 | 1,609 |
| 밝기 단독 | 949 | 924 |
| 트러블 단독 | 92 | 92 |
| 다섯 지표 개선 필요 | 1,099 | 1,075 |
| 붉은기 배제 옵션 해제 | 1,679 | 1,640 |
| 수분 미측정 | 639 | 621 |

18개 기존 시나리오의 상위 5개 제품과 순서는 동일했다. 이는 상위 결과의 품질을 입증하는 것이 아니다. 수정 목표는 잘못된 후보 범위를 줄이는 것이며, 동점 문제는 여전히 남는다.

원본 SHA-256: `7096c10e71cde631c9083e8eb351fcb75cd700c542fef23a716e6b7adabb0216`

비교는 원본 SQLite, 저장소 v1 규칙, 개발용 판정 구간으로 실행했다. 사용자 PostgreSQL에는 직접 접속하지 않았다. 원본 파일과 DB에는 쓰지 않았다.

## 현재 성분 정책 점검 결과

코드의 활성·보류 상태를 확인한 결과이며, 이번 작업에서 연구 문헌을 새로 검증하거나 효능 정책을 변경한 것은 아니다.

| 지표 | 활성 매칭 | 남은 검토 사항 |
|---|---|---|
| 수분 | 글리세린·판테놀·하이알루로닉애씨드 | 성분 존재와 완제품 효과를 구분; 함량 미상에 임의 점수 부여 금지 |
| 밝기 | 나이아신아마이드 | 사진 밝기와 색소 관련 연구 평가 대상의 연결 확인 필요 |
| 균일도 | 나이아신아마이드 | 밝기와 공유하는 근거의 중복 집계 문제 미해결 |
| 트러블 | 살리실릭애씨드 | 트러블 지표 정의와 규칙 적용 범위의 연결 확인 필요 |
| 붉은기 | 없음 | 추천 가점 보류; 배제 정책만으로 개선 효능을 주장하지 않음 |

향료·에탄올·변성알코올·멘톨·글라이콜릭애씨드·락틱애씨드·캠퍼·우레아 8개는 붉은기 개선 필요 및 배제 옵션 활성 때의 조건부 배제다. 전 사용자 대상 금지 목록이 아니다. 사용자 지정 배제는 별도로 우선 적용된다.

판테놀–붉은기, 나이아신아마이드–트러블, 우레아–수분, 소듐하이알루로네이트–수분, 세라마이드엔피–수분, 병풀추출물–붉은기 6개 규칙은 여전히 보류다. 유사 성분명이나 유도체를 자동 동일시하지 않는다.

## 검증·적용

전체 로컬 백엔드 테스트 133개 통과. 이번 추가 테스트는 13개이며 제품명 분류, 혼합 구성, 브랜드명 오탐, 명시적 얼굴 겸용, 옵션 독립성, 후보 통계와 순위 연속성을 검사한다. 회귀 테스트의 성분은 합성 fixture다. 실제 원본의 전체 후보 수 비교는 별도로 실행했다.

직전 사용자 환경의 112개에 동일하게 적용되면 125개를 예상한다. 로컬의 8개 추가 정책 비교 테스트 파일 적용 여부는 사용자 환경에서 미확인이므로 개수 차이만으로 실패라 판단하지 않는다.

```powershell
cd C:\Users\USER\Desktop\BOA-git
git apply --check "$HOME\Downloads\boa-cosmetic-backend-scope-v1.patch"
git apply "$HOME\Downloads\boa-cosmetic-backend-scope-v1.patch"
cd backend
docker compose exec api python -m unittest discover -s tests -v
```

마이그레이션·시드·프론트 수정은 없다. 추천 API가 사용하는 기존 분류 함수에 반영되므로 별도 비교 모드를 켤 필요가 없다. 기본 순위는 그대로이며 백엔드 전체가 완성됐다는 뜻은 아니다.

## 후속 순서

1. 이번 후보 범위 수정 적용.
2. 밝기·균일도·트러블 지표 의미와 성분 규칙 적용 범위 확정. 임시 점수 입력과 규칙 의미 확정은 별개다.
3. 기대 후보·배제 사유가 정해진 대표 사례로 순위 정책 평가. 대규모 동점을 임의 함량이나 임의 가중치로 해소하지 않기.
4. 결과에 따라 API 순위 정책 확정. 카탈로그 갱신 기능은 후순위 유지.
