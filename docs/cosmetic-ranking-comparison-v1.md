# 화장품 백엔드 순위 정책 비교

## 상태와 목적

2026-10-05. 추천 알고리즘은 확정 상태가 아니다. 현재 API의 규칙 매칭과 후보 필터는 유지하고, 전체 후보를 대상으로 세 가지 순위 정책을 구현·비교했다. 이 패치는 백엔드 비교 모듈·스크립트·테스트만 추가한다. 운영 API, DB, 마이그레이션, 프론트엔드는 변경하지 않는다.

## 비교 정책

| 정책 | 정렬 기준 |
|---|---|
| metric_count | 기존 매칭 지표 수 → 세트 의심 여부 → 제품 ID |
| concern_groups | 매칭 고민 그룹 수 → 세트 의심 여부 → 제품 ID |
| explicit_priority | 명시한 우선 고민의 매칭 여부 → 그룹 수 → 세트 의심 여부 → 제품 ID |

그룹 정책은 현재 나이아신아마이드 규칙이 공유하는 밝기·균일도를 하나의 색소 관련 그룹으로 묶는 **설계 가설**이다. 두 지표가 의학적으로 같다는 결론도, 논문 개수가 효능 점수라는 뜻도 아니다. 기존 `match_count`와 지표별 설명을 보존하고 별도 `group_count`를 계산한다. 향후 규칙 변경 시 이 고정 그룹도 다시 검토해야 한다.

우선 고민은 이용자가 명시해야 한다. 점수에서 자동 추정하지 않으며, 미측정·정상 판정·활성 규칙 없는 지표는 허용하지 않는다. 해당 지표에 맞는 제품이 실제 후보에 없으면 매칭을 만들어내지 않는다. 이번 실험의 우선 고민은 가정한 입력이지 실제 사용자 선호가 아니다.

## 실제 원본 카탈로그 결과

원본 제품 2,584개, 개발용 지표 구간, v1 규칙, 18개 시나리오를 사용했다. 기존 Top 5만 재정렬하지 않고, 동일 필터를 통과한 전체 후보를 복원했다. 각 정책의 후보 집합 동일성과 기존 정책의 Top 5 재현을 검사했다.

| 사례 | 후보 수 | 그룹 정책으로 순위가 바뀐 후보 수 | 기존/그룹 정책 Top 5 교집합 | 최상위 동점 후보 수(기존 → 그룹) |
|---|---:|---:|---:|---:|
| 수분 단독 | 1,648 | 0 | 5 | 1,131 → 1,131 |
| 밝기+균일도 | 949 | 0 | 5 | 632 → 632 |
| 다섯 지표 개선 필요 | 1,099 | 993 | 5 | 16 → 16 |
| 붉은기 배제 옵션 해제 | 1,679 | 1,558 | 5 | 31 → 31 |
| 수분 미측정 | 639 | 595 | 5 | 17 → 17 |
| 붉은기 단독 | 0 | 0 | 해당 없음 | 해당 없음 |

결과가 있는 모든 시나리오에서 세 정책의 Top 5 목록과 순서가 같았다. 상위 후보가 해당 요청의 활성 지표를 모두 매칭해 이번 정책 변화로 서로 구별되지 않았다. 하위 순위는 크게 바뀌었다. 예컨대 다섯 지표 사례의 수분+트러블 제품 `A000000156040`은 기존 617위에서 그룹 정책 44위로 이동했다. 이는 지표 중복 집계가 순위에 영향을 준다는 사례이며 그 제품의 효능 우수성을 증명하지 않는다.

우선 고민을 수분으로 지정하면 같은 사례에서 1,047개, 트러블로 지정하면 1,013개의 순위가 바뀌지만 Top 5는 그대로다. 단독 고민의 대규모 동점도 해결되지 않았다. 동점 수는 제품 ID를 제외한 정렬 기준이 같은 모든 후보를 세며 자신도 포함한다.

## 판단과 다음 백엔드 작업

1. 정렬식을 바꿨다는 이유만으로 추천 품질이 좋아졌다고 판단하지 않는다. 이 결과만으로 기본 API를 새 정책으로 교체하지 않는다.
2. 먼저 동점 집단의 제품 정보를 검수한다. 단품/세트, 얼굴 사용 부위, 씻어내는지 여부를 확인 가능한 출처와 검수 상태로 저장하는 설계를 진행한다. 이름만으로 추정한 결과와 확인된 정보를 구별한다.
3. 현재 활성 6개 매칭 규칙의 적용 범위를 점검한다. 지표 정의와 연구 평가 대상이 다르면 활성 범위를 좁히거나 보류한다. DB에 성분이 존재한다는 이유로 모든 성분에 효능 태그를 붙이지 않는다.
4. 함량 원문은 별도로 보존되어 있지만 대부분 누락됐고 기준도 불명확하다. 검증되지 않은 농도 환산을 점수로 사용하거나, 누락을 0으로 간주하지 않는다.
5. 검수한 대표 제품과 기대 결과를 먼저 정한 뒤 정책을 비교한다. 특히 중복 근거, 미측정 수분, 붉은기 단독, 사용자 배제, 세트 구성, 공동 점수 사례를 포함한다. 그 후 API에 순위 정책 버전과 명시적 사용자 우선 고민을 연결할지 결정한다.

임의 측정값으로도 입력 검증·경계값·규칙 조회·배제·순위 재현 검증은 가능하다. 실제 피부 상태에 대한 추천 적합성 검증은 별개다. 현재 테스트 통과는 정해진 동작의 일관성을 확인한 것이며 추천 효과를 입증하지 않는다.

## 검증과 재실행

이 작업 환경에서 전체 백엔드 테스트 120개 통과(기존 108개+신규 12개). 사용자 PC에서 실행한 결과는 아직 확인하지 않았다.

```powershell
docker compose exec api python -m unittest discover -s tests -v
docker compose exec api python scripts/compare_cosmetic_rankings.py data/beauty_catalog.db
```

비교 스크립트는 원본 SQLite를 읽고 PostgreSQL에 연결하거나 쓰지 않는다. 실행 전후 원본 SHA-256을 확인한다. DB 저장 규칙을 조회하는 운영 API와 달리 저장소의 v1 규칙 번들과 개발 구간을 사용한다. 임시 ID는 원본 제품 코드 순서로 부여하므로 사용자 PostgreSQL의 실제 Top 5와 동일하다고 단정할 수 없다.

- 원본 SHA-256: `7096c10e71cde631c9083e8eb351fcb75cd700c542fef23a716e6b7adabb0216`
- 규칙 fingerprint: `d14439693f8ff6f1cecc33a1fbf695b11d94dc2a71c5a0aaba26123d9966d41c`
- 비교 정책 버전: `cosmetic-ranking-experiment-v1`

현재 Windows 소스·PostgreSQL에 직접 접속해 검증한 결과는 아니다.
