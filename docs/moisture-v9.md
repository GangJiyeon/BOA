# 왼쪽 뺨 v9: 과거 코드 비교와 보정 모델 기반 추천 연결

## 현재 가능한 것과 미완료
과거 코드의 기본 범위 30-count 비교 지수를 표시한다. 새 표본 평균을 사용하므로 과거 코드의 32회 빠른 읽기/정수 평균과 완전히 동일한 출력은 아니다. w 명령으로 저장했던 개별 기준값은 전달되지 않았으므로 복원하지 않았다. 이 지수는 피부 수분 함량이 아니며 자동으로 추천 점수가 되지 않는다.

사용자 제공 코드: DEFAULT_SKIN_RANGE=30, wetData=airData-30, 지수=(airData-raw)/(airData-wetData)*100, 0..100 제한. w 사용 시 분모가 달라진다. 현재 기본 신호 변화율의 분모는 airData이다. 공기506/평균487.71에서 변화율3.61%, 비교지수60.97/100이다. 공기506/평균500은20, 평균491은50이다. 과거 네 사람의20~50은 이 척도로 설명 가능하지만 당시 실제 raw/w 값은 없어 정확한 재현을 증명하지는 않는다.

피부용 절대 수분율이나 건조 판정의 근거가 확보됐다는 의미가 아니다. 사용자에게서 확인된 것은 측정·피부분석 전달이며, 보정 모델은 실제 자료가 필요하다.

## 구현
- 기존 moisture_sensor.ino/Fdc2112.h에 comparison_index30_single 시리얼 항목을 추가했다. 이 값은 해당 단일 표본의 정수 비교지수다. 웹 완료값은 3초 평균에서 계산한다. BLE 원시값/프로토콜/보정은 유지한다.
- 측정 완료 화면과 저장된 피부 결과에 30-count 비교지수를 함께 표시한다.
- 서버가 운영자가 지정한 보정 모델로 센서 변화율 → 기준 장비 수치 → BOA 0..100 점수 순서로 변환한다.
- 모델은 두 개의 단조 증가 구간별 선형 곡선이다. 범위 밖 외삽/자동 보정은 하지 않는다. 값이 낮다고 임의로 확대하지 않는다.
- 모델 파일 없음/오류/검토 전/기준값 범위 밖/점수 구간 오류를 구분해 미반영 사유를 표시한다.
- 적용 시 수분 관측 기록에 보정 점수·판정·모델 버전·파일SHA256을 저장한다. 기존 SkinScore를 덮어쓰는 대신 피부 분석 조회 응답에서 최신 관측의 보정 점수를 적용한다. 센서 모델이 적용되면 기존 수동 수분 점수보다 우선한다.
- 프론트에서 이 점수를 추천 입력으로 보내며, 측정이 나중에 끝나도 자동 재조회한다. 갱신 실패 시 이전 추천임을 알리고 분석 시작 버튼으로 재시도할 수 있다.
- 예전 기록은 모델 변경만으로 재해석하지 않는다. 모델 배치 이후 새 측정부터 적용한다. 모델 파일과 검증 근거는 버전별로 별도 보관해야 한다.

## 적용(v8 적용 프로젝트)
ZIP의 backend/frontend/hardware/docs를 기존 프로젝트에 덮어쓴다.
1. backend에서 docker compose restart api
2. 프론트 npm run dev 재시작, 브라우저 새로고침
3. 시리얼 비교지수도 보려면 기존 moisture_sensor.ino를 UNO R4 WiFi/COM5로 업로드. 기존 v8 펌웨어도 웹 표시/서버 추천 연결과 호환된다.
DB 마이그레이션이나 새 npm 패키지는 없다. 기존 v7 수분 관측 테이블이 있어야 한다.

## 보정 모델 설정(아직 실제 모델 없음)
MOISTURE_CALIBRATION_PROFILE 환경변수가 빈 값이면 미적용이다. 실제 보정 데이터가 없는 지금은 그대로 둔다. 테스트 fixture의 TEST-ONLY 계수를 실제 파일로 쓰면 안 된다.

모델 필드:
- version, status(draft/reviewed), site(left_cheek), algorithm_version(cheek-auto-v1)
- reference_device, reference_unit: 비교한 장비와 원래 단위
- evidence: 해당 장치·위치·측정조건·반복성·검증 결과 자료의 위치/설명
- score_basis: 기준 장비 값을 BOA 점수 및 기존 DB 판정 구간에 대응시키는 근거
- baseline_min/max: 보정 실험에서 확인한 공기 기준값 적용 범위
- response_to_reference: [{x: 센서 변화율, y: 기준 장비 값}, ...]
- reference_to_score: [{x: 기준 장비 값, y: BOA 점수}, ...]
두 곡선 모두 x/y가 엄격히 증가해야 한다. response는 공기값 분모의 상대 변화율이며 30-count 지수가 아니다.
reviewed는 운영자가 근거를 검토했다는 설정이며 소프트웨어가 임상적 타당성을 인증하는 기능은 아니다. 기준 장비 AU를 절대 수분 %로 표기하면 안 된다.

전체 형식: python scripts/check_cheek_calibration.py --schema
파일 형식 확인: python scripts/check_cheek_calibration.py /app/calibration/left-cheek.json
실제 파일 배치 이후 backend/.env에 MOISTURE_CALIBRATION_PROFILE=/app/calibration/left-cheek.json 설정, docker compose up -d --force-recreate api로 반영한다. /app은 현재 compose의 backend 마운트 경로다.
보정 모델은 해당 단일 센서와 조건에만 적용해야 한다. 현재 BLE는 하드웨어 일련번호/설정 검증 정보를 전달하지 않으므로 여러 센서를 자동 구분하지 못한다. 센서 교체/설정 변경 시 기존 모델을 끄고 재검증해야 한다.

## 필요한 실제 자료
같은 왼쪽 뺨 위치에서 BOA 측정과 비교용 피부 수분측정기 값을 짝지어 기록해야 한다. docs/left-cheek-pairs.csv는 빈 기록 양식이다. 개인정보 대신 참여자 코드를 사용한다. 같은 참여자의 반복 표본을 학습/검증 양쪽에 나눠 성능을 부풀리지 않는다. 기준 장비가 없어도 예전 상대지수 재현은 가능하지만, 피부 수분 상태를 판정하는 계수를 검증할 수는 없다.

## 검증
- 프론트 빌드, 자동 측정 상태 및30-count계산 테스트 통과
- React DOM: 완료→첫 사진→분석→저장 중 메뉴 이동→보정점수 반영→추천 자동 재조회 통과
- 백엔드 수분 관련12개, 피부13개, 추천30개 테스트 통과
- 가상 모델로 실제 추천 응답의 moisture 성분 매칭 생성 확인. 이는 모델 연결 검증이며 실제 피부 정확도 검증이 아니다.
- 모델 없음/검토 전/잘못된 파일/범위 밖, 저장 재시도 시 과거 모델 결과 유지 검증
- C++ 호스트 테스트 및 UNO R4 WiFi 대상 빌드 성공: 프로그램93,884바이트/전역11,812바이트
- 사용자 장치 실제 업로드 및 기준 장비 비교는 수행하지 못했다.
