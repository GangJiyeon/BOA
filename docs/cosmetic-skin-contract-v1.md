# 피부 분석 결과와 추천 계약

2026-10-05. POST /api/cosmetics/recommendations/preview의 scores는 기존 점수 객체와 피부 분석의 scores 배열을 모두 받는다. 전체 분석 응답에서 scores를 추출해서 전달한다. 지표 코드로 연결하고 수분 누락은 미측정(None)으로 처리한다. 필수 사진 지표 누락, 중복, 알 수 없는 코드, 정수/범위 오류는 422다. 배열의 higher_is_better 및 category_name은 현재 DB 정의·판정 구간과 대조한다. 불일치는 자동으로 뒤집거나 무시하지 않고 422로 반환한다. 과거 분석 라벨이 현재 DB 구간과 다르면 재분석하거나 기준 버전을 먼저 맞춰야 한다.

## 의미에 따른 적용 범위

기본 score_semantics는 photo_v1이다. 현재 피부 분석 코드의 brightness는 평균 명도, uniformity는 명도 표준편차의 역점수, trouble은 국소적인 붉은 반점 면적 비율이다. 이 값으로 색소침착·면포를 확인하지 않으므로 밝기·균일도·트러블 성분 매칭은 적용하지 않는다. 개선 필요 상태는 유지하고 deferred_metrics로 보류한다. 수분은 측정값이 있고 개선 필요이면 기존 수분 규칙을 사용한다. 홍조 가점은 기존처럼 보류하며 선택 가능한 조건부 배제 정책은 유지한다. 질환 진단 또는 제품 효능 인증이 아니다.

기존 성분 규칙 실험은 점수 객체와 score_semantics=development_assumption으로 명시적으로 요청한다. 피부 분석 배열은 이 모드를 사용할 수 없다. 원본 규칙 DB를 변경하거나 삭제하지 않는다. 배열 입력뿐 아니라 기본 점수 객체에도 photo_v1을 적용한다.

예시(수분50, 홍조15, 밝기71, 트러블92, 균일도91)는 개선 대상 1개, 평가 가능 0개, trouble 보류, 추천 빈 목록이다. 이는 오류가 아닌 측정 의미에 맞는 보류 결과다. 수분 미측정이고 사진 지표만 개선 필요인 경우에도 제품을 임의로 추천하지 않는다.

## 화면과 통합 범위

기본 화면은 피부 분석 JSON 입력이다. 전체 분석 응답 또는 scores 배열을 붙여넣고 추천을 요청한다. 별도 개발용 모드는 기존 슬라이더를 유지한다. API 호출자는 분석 응답의 scores를 추천 요청에 넣으면 된다. 사진 업로드 화면에서 분석 완료 후 자동 호출하는 연결은 이번 범위에 포함하지 않는다.

검증: 추천 테스트154개(새 계약 테스트8개 포함), 프런트 TypeScript/Vite 빌드, oxlint. API 테스트는 임시 SQLite이며 사용자 PostgreSQL·실제 사진·센서는 검증하지 않았다. DB 스키마 및 기존 규칙 데이터 변경 없음.
