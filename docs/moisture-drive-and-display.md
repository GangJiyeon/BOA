# 구동 선택과 표시 환산 수정 — 2026-10-28

## 적용 범위

기존 `hardware/arduino/moisture_sensor`에 적용한다. 새 별도 실험용 스케치를 만들지 않는다. Arduino UNO R4 WiFi / Wire1 / Qwiic / FDC2112, 피부 접촉 한 번·고정3초를 유지한다. 기존 AI Studio·카메라 작업도 보존한다. DB 마이그레이션은 추가하지 않는다.

## 구동 변경

기존 전류 코드는15(레지스터0x7800)로 고정돼 있었다. 새 펌웨어 `moisture-acquisition-v15`는 피부가 닿지 않은 부팅 시점에 정상 전류 모드의 코드31부터0까지 내림차순으로 확인한다. 각 후보는 sleep → 설정 쓰기·읽기 확인 → wake 순서로 적용한다. DATA의 경고와 STATUS의 watchdog·진폭 경고가 없으며 출력 레일에 닿지 않는 새 변환8개가 연속 확인된 가장 높은 코드를 선택한다. 각 후보는 최대250ms 동안 확인한다. 정상 전류 모드의 범위를 벗어나거나 HIGH_CURRENT_DRV를 켜지 않는다.

그 뒤 기존 분주비·gain headroom 조사와 최종 설정 확인을 한다. 선택 전류는 공기 보정과 접촉 측정 중 바꾸지 않는다. 따라서 다른 전류의 공기값과 피부값을 섞는 보정 오류를 만들지 않는다. 수분이 더 높은 접촉 부하를 감당할 여유를 늘리려는 설계 가설이며, 실제 장치에서 경고가 해결된 것을 확인한 것은 아니다. 경고가 없다는 사실도 진폭1.2~1.8V를 직접 측정했다는 뜻은 아니다.

BLE v5 특성 `98b10006-e8f2-537e-4f6c-d104768a1214`를 추가한다. 패킷은 기존20바이트이고, 중복 상대 percent 필드를 전류 코드와 STATUS 진폭 방향으로 대체한다. DATA의0x1000 경고가 있어도 STATUS에 방향이 없으면 unknown을 유지한다. 경고 count는 진단용이며 정상 측정값으로 사용하지 않는다. 기존 v1~v4 특성은 유지하고 새 프론트는 v5를 우선 선택한다.

접촉 중 지속 경고가 발생하면 3초에서 결과 없이 종료한다. 숫자를 내기 위해 경고를 끄거나, 경고 표본을 정상으로 바꾸거나, 시간을 연장하지 않는다. 진폭 경고로 표본이 부족하면 연결 끊김과 구분해 표시한다.

## 표시 변경과 판정의 분리

신규 normalization은 `boa-capacitance-display-v2`다. 대표값은 기존처럼 마지막1초의 중앙값이다. 공기 기준B, 대표값X에 대해:

`capacitance_increase_percent = 100 * (((B+170)/(X+170))^2 - 1)`

`display = clamp(round(capacitance_increase_percent * 10), 1, 100)`

×10과 상한100은 UI 표시 설계다. 피부 수분의 검량선이나 임상 정상 범위가 아니다. 상한100을 넘는 반응도 원시 표본과 물리 반응률을 보존하며, 확대한 점수로 추천 상태를 다시 분류하지 않는다. 실험 판정 라벨과 표시 점수는 서로 다른 척도이므로 표시 점수의33/66 등으로 판정하지 않는다.

사용자가 제공한 audit(3)의 두 정상 측정 재생:

| 기록 | 공기B | 마지막1초 중앙값X | 정전용량 증가율 | 이전 표시 | 새 표시 |
|---|---:|---:|---:|---:|---:|
| 세안 전 |2538|2506|2.405929%|3|24|
| 세안 후 |2538|2502|2.712763%|3|27|

두 오류 기록은 각각 진폭 경고28개로 정상값이2개·1개뿐이다. 새 구동 전류로 재측정하지 않은 기존 파일만으로 경고 해소를 증명할 수 없으므로, 재생 시에도 실패를 유지한다.

과거 `hydration-estimate-pnj-2023-v1` 기록은 이전 표시를 유지한다. 서버는 신규 척도를 별도 인식하지만 기존 실험 모델의 상태를 먼저 계산하고 추천 규칙에 전달한다. 표시에 맞추려고22/45 경계를 낮추지 않았다. **기존 PNJ 상태 경계가 BOA 피부 건조 상태를 정확하게 판정한다는 근거는 여전히 확보되지 않았다. 이 배포는 그 문제까지 해결한 배포가 아니다.**

## 검증 범위

호스트 C++ 시험으로 경고가 나는 전류를 건너뛰고 정상 후보를 선택하는지, 접촉 경고 중 전류가 바뀌지 않는지 확인한다. BLE v5의 전류·경고 방향·구형 호환, 고정3초 1회 종료, 표시 전후 추천 정책·후보 동일성, 이전 기록 보존과 새24/27 환산을 소프트웨어 시험한다. 피부 상태의 실제 정답을 확인하는 시험과 구분한다.

이 환경에는 Arduino 타깃 코어가 설치돼 있지 않고 코어 다운로드가 차단돼 있어 UNO R4 타깃 빌드를 수행하지 못했다. 실제 장치 업로드·접촉 경고 개선·피부 판정 정확도 시험도 수행하지 않았다.
