# v10: 단일 접촉 측정과 실험적 추천 보조 연결

## 사용자 흐름
연결 → 공기 기준 보정 → 왼쪽 뺨에 한 번 접촉 → 안정화 → 3초 새 표본 수집 → 자동 완료.
분리 접촉 3회는 요구하지 않는다. 측정 중 경고, 표본 누락, 접촉 해제, 불안정 신호에만 재측정을 안내한다.
완료 후 손을 뗀 상태가 확인되기 전에는 같은 접촉으로 중복 저장하지 않는다.

## 적용
v9/v9.1이 적용된 프로젝트에 ZIP의 frontend/backend/hardware/docs를 덮어쓴다.
backend에서 docker compose restart api 실행. 프론트 npm run dev를 재시작하고 새로고침.
Arduino IDE에서 기존 hardware/arduino/moisture_sensor/moisture_sensor.ino를 열고 UNO R4 WiFi/COM5로 업로드.
세 탭은 한 스케치이므로 업로드는 한 번만 한다. Gemini 수정본 대신 이 폴더의 파일들을 함께 사용한다.
펌웨어 시작 로그: BOA firmware: moisture-cheek-capacitance-v10
추가 패키지/DB 마이그레이션/보정 모델 환경변수는 필요 없다. 기존 v7 관측 테이블은 필요하다.

## 물리 계산과 표시 척도
현재 고정 설정: gain=16, offset=170, FIN=2, FREF divider=11.
TI 공식에 따라 f(count)=2*fREF*(count+170)/65536이며, 같은 회로·클록에서:
capChange(count) = (((baseline+170)/(count+170))^2 - 1)*100.
각 표본을 변환한 후 평균을 낸다. 평균 count를 먼저 변환하는 방식과는 미세한 차이가 있다.
이는 회로 전체 정전용량의 상대 변화다. 순수 각질층 정전용량이나 절대 피부 수분량이 아니다.
실제 L 및 클록 오차가 약분되는 비율을 사용하며, 공칭값만으로 정확한 pF를 주장하지 않는다.
BLE의 기존 relativePercent 필드는 호환성을 위해 기존 의미로 유지한다. 펌웨어 시리얼에 capacitance_change_pct를 추가하고, 웹/서버는 원시값에서 독립적으로 재계산한다.
기존 펌웨어의 하드웨어 설정과 호환되지만, 설정을 변경한 다른 펌웨어에는 그대로 적용하면 안 된다. BLE에는 설정 인증/센서 일련번호가 없다.

표시 지수 = clamp(mean(capChange(samples))/capChange(baseline-30)*100, 0, 100).
30 counts 표시는 과거 코드와 비슷한 범위를 유지하기 위한 임시 표시 기준이다. 사람들의 피부를 측정해 얻은 임상·실측 보정 계수가 아니다.
예: baseline506/mean493.71이 일정한 표본이면 용량 변화 약3.738%, 표시 지수 약39.33%. 예전40.97%와 척도가 다르므로 이전 수치와 직접 비교하지 않는다.
100%는 피부 수분 포화가 아니라 표시 상한이다. 상한 도달 결과는 저장하되 추천 보조 입력에서 제외한다.
v1 결과는 기존 식/의미로 유지한다. v2 결과만 새 계산/보조 추천을 사용한다.

## 단일 접촉 품질 검사
기존 새 표본, 3초, 최소25개, 시간간격/순번, 경고 검사를 유지한다.
추가: 정전용량 변화율 범위≤2%p, 표준편차≤0.75%p, 처음5개와 마지막5개 평균 차이≤1%p.
이 허용치는 초기 공학 설정이며 임상 기준이 아니다. 실제 장치의 실패율과 기록을 보고 조정할 대상이다.
프론트와 서버에서 모두 검사한다. 서버는 브라우저가 계산한 점수를 받지 않고 raw 표본에서 계산한다.
안정적인 신호가 접촉 압력·면적·절대 정확도를 보증하지 않으며, 단일 접촉으로 재접촉 반복성을 검증할 수는 없다.

## 추천 연결
임상 수분 점수(SkinScore)를 생성하지 않는다. used_for_scoring=false를 유지한다.
유효한 v2 결과는 recommendation_eligible=true로 저장되며, 프론트는 analysis_id와 measurement_id를 추천 요청에 전달한다.
서버는 해당 분석에 저장된 관측을 조회·검증한다. 숫자만 입력해 보조값을 위조하는 경로는 없다(기존 앱의 분석 접근권한 구조는 그대로다).
사진 분석 후 저장이 끝나도 자동으로 추천을 갱신한다. 저장 실패/갱신 실패는 화면에 표시한다.
기존 보정/수동 수분 점수가 있으면 상대 지수를 중복 반영하지 않는다.

보조 정책 cheek-aux-tie-v1:
- 활성 보습 성분 규칙을 가진 제품에 0.25*(1-index/100)의 실험적 보조값을 부여한다.
- 기존 순위 조건(지표 수/고민 그룹/우선 고민/세트 여부)이 모두 같은 후보 안에서만 보조값을 비교한다.
- 사진 지표 점수, 개선 필요 판정, 하드 배제, 후보 포함 조건을 변경하지 않는다.
- 매칭 성분 개수는 가산하지 않는다. 농도·제형·개별 효능을 추정하지 않는다.
- 이 보조값은 임상적 효과 크기가 아니다. 현재는 보습 성분 함유 유무가 동일하면 보조값도 같으므로 지수 차이만으로 제품 순서가 달라지지는 않는다. 특히 일상 관리 후보가 모두 보습 성분을 포함하면 순위는 그대로일 수 있다.
- 기존 동점이 없거나 보습 성분 차이가 없으면 결과가 달라지지 않는 것이 정상이다.
화면에는 보조 반영 여부와 해당 제품의 성분을 표시한다. 상대 지수만으로 건성/정상/지성을 판정하지 않는다.

## 확인된 범위
프론트 빌드, 자동 측정 상태/물리식/불안정 신호 거부 테스트 통과.
React DOM: 1회 접촉 완료, 중복 완료 방지, 저장 중 화면 이동, 분석 연결, 보조 추천 및 기존 보정 추천 자동 재조회 통과.
백엔드 기존 수분12개, 추천168개, 새 계산/보조 연결4개 테스트 통과.
C++ 호스트에서 실제 ino 포함 테스트 및 오프셋 계산 테스트 통과. 이번 실행 환경에서는 UNO R4 보드 대상 빌드/실제 장치 업로드는 수행하지 않았다.
실제 피부 정확도 및 재접촉 반복성은 아직 검증되지 않았다. 사용자가 실제 결과·전체 측정 기록을 전달하면 단일 접촉 내 변동/실패 원인을 추가 분석할 수 있다.
