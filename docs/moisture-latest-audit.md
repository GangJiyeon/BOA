# 새 측정 로그 검토와 단일 접촉 안정화 수정

2026-10-28. 대상은 사용자가 새로 올린 측정 결과 JSON과 전체 측정 기록 JSON이다.

## 실제 데이터에서 확인한 내용

| 항목 | 값 |
|---|---:|
| 공기 기준 | 2540 counts |
| 공기 확인 표본 | 21개, 모두2540 |
| 완료 구간 | 31개, 3.035초 |
| 접촉 평균 | 2497.8387 counts |
| 접촉 중앙값 | 2498 counts |
| 표시식 재계산 | 3.0756117% |
| 정전용량 증가율 평균 | 3.1858682% |
| 시작5개/종료5개 평균의 차이 | 0.4486237%p |
| 종전 허용치 | 0.4778802%p |
| 전체 로그의 완료 이벤트 | 1회 |
| 표본 순번 누락 | 없음 |

표시식은 `100 × [1 − ((count + 170) / (baseline + 170))²]`의 중앙값이다. 표본별 정전용량 증가율은 별도 계산량이므로 표시값과 같을 필요가 없다.

공기 표본의 표시상 변동이0이라는 사실만으로 아날로그 잡음이0이라고 결론 내릴 수는 없다. 새로운 count 범위와 약0.073%p의 출력 한 단계 변화는 이전보다 촘촘한 출력 설정과 일치한다. BLE 로그에는 레지스터 readback이 없어 실제 분주비까지 직접 확인한 것은 아니다. 측정 조건이 같다는 보장이 없어 이전 측정과 비교해 피부 수분 정확도가 몇 배 개선됐다고 주장하지 않는다.

## 발견한 완료 판정 문제

완료 구간은2501에서2495까지 한 방향으로 내려간다. 전체 기록에서도 접촉 감지 이후 계속 낮아졌고, 완료 직후에도2494까지 변했다가2538 근처로 돌아갔다. 센서 신호 반응은 있지만 완료 시점에 안정된 신호였다는 근거는 부족하다. 이 움직임의 원인이 압력, 접촉 면적, 시간에 따른 변화 중 무엇인지는 로그만으로 특정할 수 없다.

종전 기준은 정전용량 증가율 평균의15%를 변화 허용치에 사용했다. 따라서 반응이 커질수록 허용하는 시작/종료 차이도 커져 이번 완만한 하강 구간을 통과시켰다.

## 적용한 변경

- 새 측정에는 기존 허용치에 더해 시작5개와 종료5개의 구간 내 표준편차를 사용한다. 두 구간 중 큰 표준편차의3배와1-count 변화량 중 큰 값으로 허용치를 제한한다.
- 식: `새 허용치 = min(기존 허용치, max(1-count 변화량, 3 × max(시작 구간 SD, 종료 구간 SD)))`.
- 이번 기록을 새 기준으로 평가하면 허용치는 약0.1034730%p다. 실제 시작/종료 차이0.4486237%p가 이를 넘으므로 완료로 확정하지 않는다.
- 이 허용치는 공학적 안정성 정책이다. 임상적인 수분 정확도, 통계적 신뢰구간 또는 접촉 압력의 적절성을 보장하는 기준은 아니다.
- 같은 한 번의 접촉을 유지하며 최근3초 구간을 갱신한다. 값이 안정된 구간이 확보되면 결과를 한 번만 확정한다. 새 접촉이나 별도의 완료 버튼은 요구하지 않는다.
- 접촉 감지부터 최대10초 안에 안정되지 않으면 이번 시도를 종료한다. 자동 재시작하지 않는다.
- 안정화 대기 중에는 진행률을100%로 고정하지 않고 대기 표시와 남은 시간을 보여준다.
- 서버도 새 측정에 같은 기준을 적용한다. 기준을 통과하지 못한 새 결과는 저장하지 않으며 추천에도 전달하지 않는다.
- 분석 결과 카드에서 최근 알고리즘의 값을 잘못 ‘이전 정전용량 실험 지수’로 표기하던 문제를 수정하고, 한 자리 소수 표시를 맞췄다.

계산식 자체와 원시값은 확대하지 않는다. 기존 기록의 해석을 바꾸지 않기 위해 새 측정의 내부 알고리즘 식별자는 `skin-auto-v6`이다. 이전v3/v4/v5 기록의 계약은 보존한다. 이번 변경은 기존 기록을 소급해서 무효화하거나 삭제하지 않는다.

## 검증

- 새 실제 로그를 재생하면 기존3.08% 구간에서 완료하지 않는다. 이어지는 실제 급격한 복귀 구간도 완료로 처리하지 않는다.
- 실제 로그의 기존 완료 시점까지 재생한 다음, 마지막 값이 그대로 유지된다는 **합성 표본**을 별도로 이어 붙이면, 같은 접촉 안에서 한 번만 완료된다. 실제 사용자가 그만큼 유지했거나 안정화에 성공했다는 뜻은 아니다.
- 같은 재생을 React 화면과 BLE 패킷 경로에서도 검증했다. 기존 완료 시점에는 완료 문구가 없고 안정화 대기가 표시된다. 합성 안정 구간이 생긴 뒤에만 완료된다.
- 서버 API에서 하강 구간은422, 미저장을 확인했다. 합성 안정 구간은 저장·동일 요청 재전송·추천 보조 전달까지 검증했다.
- 백엔드46개 테스트, 프론트 자동 측정 회귀, DOM 통합, production build 통과.

계속 남아 있는 한계: 이번 숫자는 센서의 정전용량 반응률이며 피부 수분 함량 백분율로 보정된 값은 아니다. 정확한 피부 수분율이나 건조 판정이 검증 완료된 것으로 사용하면 안 된다. 현재 추천 연동은 기존의 실험적 보조 반영이다.

## 적용

이 ZIP은 직전 센서 취득 개선을 적용한 현재 BOA 프로젝트용 프론트엔드/백엔드 업데이트다. **아두이노 코드는 변경하지 않으므로 재업로드하지 않는다.**

1. 프로젝트 루트에 ZIP 내용을 덮어쓴다.
2. 백엔드를 다시 시작한다. 소스가 이미지에 포함되는 환경까지 적용하려면 다음 명령을 사용한다. DB 볼륨을 삭제하는 명령은 사용하지 않는다.

```powershell
cd C:\Users\USER\Desktop\BOA-git\backend
docker compose up -d --build api
```

3. 프론트엔드를 다시 실행한다.

```powershell
cd C:\Users\USER\Desktop\BOA-git\frontend
npm run dev
```

4. 브라우저를 새로고침하고 센서를 연결한다. 이전 완료값이 남아 있으면 다시 측정을 누른다. 공기 보정 후 피부에 한 번 대고, 안정화 및 완료 안내가 나올 때까지 같은 위치에서 유지한다. 숫자를 올리기 위해 더 세게 누르지 않는다.

이전 패치의 문서는 당시 변경 이력이며, 이번 적용은 이 문서를 따른다. DB 마이그레이션이나 새 장비는 필요하지 않다. ZIP에 포함된 실제 로그 기반 테스트 자료는 식별자와 측정 날짜를 제거했으며, 합성 자료와 구분해 사용한다.
