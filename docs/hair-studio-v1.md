# AI 헤어 스튜디오 v1

현행화: 2026-11-15, 현재 로컬 코드 기준. 구현 개요는 이 문서, 함수별 학습 설명은 [헤어 합성 학습 가이드](hair-synthesis-study-guide.md)를 참고한다.

직접 업로드한 사진과 카탈로그 스타일 또는 헤어 추천 결과를 사용해 합성하고, 브라우저에서 32가지 프리셋과 HSV 슬라이더로 머리색을 바꾸는 기능. 추천 분석을 먼저 해야만 사용할 수 있는 구조는 아니다.

- 현재 구현을 설명하는 본문과 과거 실험 수치를 구분했다. 외부 AI의 최신 가격·모델 지원·생성 속도를 새로 측정한 문서는 아니다.
- 이 문서를 갱신하면서 코드·DB·이미지 파일은 변경하지 않았다.

## 흐름

1. 프론트: 직접 업로드 사진 + 카탈로그 스타일, 또는 헤어 추천 결과 + 분석에 쓴 정면 사진(첫 장)으로 `POST /api/studio/hair-renders`. `run_id`는 추천에서 가져올 때만 보낸다.
2. 백엔드 요청 처리: 인증·스타일·사용량 검사 후 사진을 디코딩한다. 얼굴 없음, 기울기 10° 초과, yaw 근사 지표 0.35 초과, 축소 후 얼굴 폭 120px 미만이면 AI 호출 전에 422. 이미지가 10MB를 넘으면 413. 통과하면 pending 행 저장 후 202를 반환하고 백그라운드 작업을 등록한다.
3. 백그라운드 합성
   - Flash(`gemini-3.1-flash-image`) 1회, 2K 출력: 원본 세 장 나란히(16:9 등 출력 비율에 맞게 바깥 패딩) + 카탈로그 스타일 사진 → 어두운 갈색(레벨 4) `mid`, 중간 갈색(레벨 7) `brown`, 밝은 펄 블론드(레벨 10) `light`
     - 밝은 칸은 펄 블론드: 베이지는 피부와 색 거리 약 8로 앞머리 가닥과 이마가 구분 안 됨, 펄은 색 거리 약 12
     - 스타일 참조 사진은 배경 흰색 + 눈썹 아래 얼굴 피부만 회색으로 가려 보냄 (이마까지 가리면 앞머리가 지워져 이마가 훤한 듬성한 앞머리로 생성) (선명한 정면 사진이면 AI가 참조 모델 얼굴·구도를 그대로 그려 사람이 바뀜)
     - 프롬프트로 세 칸 얼굴 크기·위치 고정 + 구도 고정(FRAME_LOCK: 확대·아래로 내림 금지, 머리 위 여백·표정 유지, 커진 머리는 칸 밖으로 잘리게), 목표 스타일의 컬·질감·앞머리 숱·가는 시스루 가닥은 유지하고 잡음만 줄이도록 지시. 모든 스타일을 매끈하게 펴거나 앞머리를 일괄 두껍게 만들지 않음
     - 과거 실험에서는 칸당 원본의 약 1.4배 해상도, 세 칸 머리 겹침 0.93~0.97을 기록함. 현재 2K는 세 칸 전체 출력 요청 크기이며 해당 비율을 보장하지 않음
     - 늘린(패딩) 부분은 흐려서 넣음 (가장자리 복사 줄무늬를 AI가 따라 그려 정수리 위에 섞임)
     - 여러 칸을 새로 그리게 하면 얼굴을 정면으로 돌려 구도가 바뀜 → 같은 원본을 미리 세 칸으로 배치해 편집시킴. 과거 실험의 얼굴 위치 차이 2~4px는 보장값이 아님
     - 세 베이스 모두 각각 원본 위에 합성 (밝은 쪽을 어두운 베이스 위에 붙이면 가장자리에 어두운 머리가 비쳐 염색 때 검은 외곽선)
     - AI 호출은 1회만 (재시도하면 2분 넘음), 칸끼리 실루엣 맞춤 후처리는 없음 (어두운 칸에만 있는 머리를 밝은 색으로 칠해 넣으면 외곽이 뿌옇게 빛나고 이마에 유령 가닥, 프롬프트로 칸끼리 같은 머리를 그리게 함)
     - 잘못 생성 판정: 원본 대비 얼굴 크기 12%(5~9%는 정렬로 맞춰져 통과)·고개 기울기 4°·좌우 돌림 0.15 넘게 다르거나 정렬 후 남는 넓이 80% 미만 → 바로 실패 처리(다른 사진 안내), 실패한 요청은 비회원 횟수에서 안 셈
       - 기준은 생성 20건 실측 (정상 최대 3.3%·0.8°·0.065·최소 88%, 망한 건 7.8%·12.2°·60%)
     - 카탈로그 사진은 사람 밖 배경을 흰색으로 덮어 보냄 (표에서 잘라 옆 칸 이름표가 섞임, "Flower perm" 글자 때문에 생머리가 곱슬로 생성된 적 있음)
   - 원본 사진 속 머리색을 `hair_hex`로 저장 (원본 사진 대신 색만)
   - 원본 위에 새 머리와 원래 머리가 사라진 자리를 합성. 눈·코·입과 원본 얼굴 윤곽 보존을 우선하지만 이마·가려졌던 피부·턱 아래는 생성 결과를 사용할 수 있음. 경계 블렌딩·JPG 재인코딩도 있어 모든 얼굴 픽셀의 완전 동일성을 보장하지 않음
     - 분할 모델이 놓친 피부 위 얇은 원래 머리 가닥(원본이 AI 피부보다 확연히 어두운 곳)도 AI 결과로 (눈꼬리 옆 잘린 가닥 자국)
     - 원래 머리에 가려졌던 볼·턱은 AI 결과로 채움 → AI가 좁힌 턱선을 원본 윤곽에 맞춰 조각별 변형
       - 변형은 윤곽선에서 이미지 폭 6% 안쪽 피부만, 변형량은 흐려서 적용 (테두리까지·머리까지 변형하면 옆머리·옷이 휘고, 삼각형 경계마다 턱선이 꺾임)
     - 원본 얼굴이 AI 얼굴보다 넓으면 볼 위 AI 가닥이 원본 피부에 덮여 머리가 휘어 보임 → AI 머리 근처·눈코입 밖에서 색이 확연히 다르면 AI 가닥 유지
     - AI 결과는 눈꼬리·콧대·코·눈썹 랜드마크로 원본에 맞춰 크기·회전·위치 정렬 (입·턱까지 쓰면 AI 표정 차이에 끌려 눈썹 위 머리가 몇 px 뜸)
     - 그다음 머리 실루엣 가운데(정수리~눈썹 높이)를 원본 머리 가운데에 맞춰 좌우 이동 (AI가 두상·가르마를 한쪽으로 치우쳐 그림, 얼굴 폭 6%까지, 눈썹 위만 옮기고 눈 높이부터 0, 사진 좌우 끝도 0)
     - 얼굴 정렬로 AI 칸 밖이 된 가장자리는 세 베이스 모두 같은 크기로 잘라냄 (늘리기·거울·메우기 모두 줄무늬·지그재그), 결과가 원본보다 몇 % 작음
     - 눈썹 아랫선 위(이마·눈썹·앞머리)는 AI 결과 통째로 (얇은 앞머리 가닥이 잘리지 않게), 피부 톤은 원본에 맞춤
     - 눈두덩은 원본 피부에 AI 앞머리 가닥만 (윗눈꺼풀 바로 위까지 통째로 쓰면 AI 쌍꺼풀 선이 원본 위에 겹쳐 두 겹), 볼 위 AI 가닥 살리기도 눈 아래부터 (색 차이로 AI 쌍꺼풀 선을 가닥으로 잡음)
     - 눈(눈꼬리·쌍꺼풀 포함)·눈코입 안쪽은 마지막에 원본으로 고정, AI 머리가 확실히 덮은 곳만 AI (원래 옆머리 지우는 범위가 눈꼬리까지 닿아 AI 눈꼬리가 섞임)
     - 눈썹은 원본 (AI가 칸마다 눈썹을 연하게·다르게 그림, 밝은 칸은 회색으로 흐려짐), AI 머리가 확실히 덮은 곳·원래 머리가 덮던 눈썹만 AI
     - 목 피부는 원본 목 피부색에 맞춤 (볼 기준만으로는 AI 목이 밝게 남음), 이마 피부(앞머리 사이)는 넓게 흐린 원본·AI 피부 평균을 자리마다 비교해 25% 가중치(`FORE_RELIGHT=0.25`)로 보정 (AI가 앞머리 그늘을 진하게 그려 이마가 L 60쯤 어두움, 한 값으로 통째로 맞추면 하얀 띠), 원본 이마 윗선 위 두피는 안 건드림
     - AI가 다시 그린 배경은 원본 배경 톤에 맞춤
     - 턱 아래(몸·옷)는 몸 기준으로 한 번 더 정렬 (AI가 몸을 몇 % 작게·옆으로 그려 원래 긴 머리 자리의 어깨·팔이 어긋남)
       - 크기 ±10%, 가로·세로 차이 5%, 회전·기울어짐 3° 넘으면 건너뜀 (옷 반복 무늬에 속아 몸이 비틀리고 가장자리 줄무늬)
     - 턱 아래는 몸 기준으로 맞춘 AI 결과 통째로 (원본 피부와 AI 피부를 이어 붙이면 톤·그늘 차이로 경계선이 보임), 옷 디테일은 AI 버전
   - 베이스별 머리 마스크 PNG 생성 (MediaPipe selfie multiclass), 밝은 베이스는 guided filter·피부 제외 후 살짝 흐림. 외곽 팽창과 강도 증가(제곱근)는 제거함. 밝은 베이스에만 머리 ROI·겹치는 조각을 재분할해 확률을 혼합함
     - 밝은 베이스는 이마 구간에서 피부와 색(a·b)이 먼 픽셀을 가닥으로 더함 (분할 모델이 펄 가닥을 놓쳐 하얀 줄, 펄은 피부와 밝기는 비슷하지만 붉은기·노란기가 확연히 적음), 보이는 눈썹만 제외 (눈썹 자리가 머리색에 가까우면 칠함)
       - 기준 피부색은 이마에서 보이는 피부 (볼은 블러셔로 붉어 맨 이마가 칠해짐), 가는 가닥만 더하고 넓은 덩어리는 뺌, 더할 양이 이마의 15%를 넘으면 아예 안 더함
4. 프론트: `GET /api/studio/hair-renders/{id}` 2초 간격 최대 90회 폴링 → 완료되면 캔버스에서 색 변경. 화면의 단계 문구는 실제 서버 진행률이 아닌 경과 시간 안내이며 폴링 취소가 서버 작업 취소를 뜻하지 않음
   - 기본은 어두운 갈색, "원래 머리색" 칸(`hair_hex`) + 32색 프리셋 (카키·올리브·민트·코랄·골드·라벤더·애쉬퍼플·블루그레이는 칠한 느낌이 강해 뺌)
   - 베이스는 `pickBase`: 사진마다 세 베이스 머리 평균 밝기를 재서 목표색 밝기에 가장 가까운 것 (밝혀야 하는 거리는 1.6배로 계산, 어두운 베이스를 밝히면 회색·떡짐), light는 앞머리 마스크가 가장 불안정해 brown을 L 38 넘게 밝혀야 할 때만 (밝은 금발·파스텔·실버)
     - 밀크브라운·밀크티베이지·애쉬베이지·허니블론드·카퍼·오렌지브라운·핑크브라운·애쉬핑크·피치핑크·애쉬블루·애쉬그레이는 light 고정 (`lockBase`, brown에서 칠하면 눈썹까지 물들어 부자연스러움), 밝은 베이스에서 어둡게 내릴 때는 명암 그대로
   - 칠한 뒤 머리 평균 Lab을 재서 목표 hex에 맞게 1회 보정 (평탄화한 픽셀 인덱스를 8씩 건너뛰어 표본 추출. 과거 특정 실험에서 32색 평균 오차 Lab 1.0·최대 3.3 기록), 프리셋은 채도·밝기 깎는 값 없이 tex·vari만
   - 세 베이스를 합성 완료 시 함께 제공하므로 모든 프리셋은 추가 AI 요청 없이 바로 변경
   - 아주 어두운 색(L < 25)은 윤기(밝은 쪽 명암)는 그대로, 그림자만 눌러 칠한 덩어리처럼 보이지 않게

## 과거 비용·시간 기록 — 현재 견적 아님

아래는 기존 개발 과정에서 적은 추정값이다. 최신 요금·환율·실측 응답 시간을 확인한 값으로 사용하지 않는다. 현재 코드의 기본 모델 설정은 `gemini-3.1-flash-image`이며 `STUDIO_STYLE_MODEL`로 변경 가능하다. 화면은 AI 생성 약 1분과 후처리 대기를 안내하기도 한다. 확실한 호출 구조는 합성 시작 시 AI 1회, 이후 색 변경 시 추가 AI 호출 없음이다.

| 단계 | 모델 | 비용 | 시간 |
|---|---|---|---|
| 스타일 합성 (세 베이스, 2K) | Flash | 약 $0.10 | 약 20초 |
| 머리 옮겨 붙이기·마스크·색 변경 | 로컬 | 추가 AI API 요금 없음. 서버·브라우저 자원 사용 | 당시 수 초 기록 |

당시에는 1회 약 $0.10(약 140원, 2K 출력 1,680토큰)으로 추정했다. 현재 비용 상한이나 보장 가격이 아니며 실패 판정도 이미 실행한 외부 요청 비용을 되돌리지 않는다.

## API

- `POST /api/studio/hair-renders` (multipart: `photo`, `style_id`, `run_id?`) → 202 `HairRenderRead`
  - 촬영 동의 필요(`require_analysis_actor`), 비회원 하루 `GUEST_DAILY_LIMIT_STUDIO`회
  - 얼굴 없는 사진은 AI 호출 전 422
  - 일반 모드는 업로드 원본 파일을 저장하지 않음. 생성 결과에는 얼굴이 포함되며 디버그 모드 예외는 아래 참고
- `GET /api/studio/hair-renders/{id}` → 본인(같은 회원·비회원 세션) 결과만, 아니면 404
  - `mid`, `brown`, `light` 베이스와 `hair_hex` (합성 완료 시 세 베이스 제공)
- `GET /api/guest/quota` 응답에 `studio` 추가

## 저장

- 결과 이미지: `backend/static/studio/{asset_dir}/` (mid.jpg, brown.jpg, light.jpg와 각 *_mask.png, 완료 시 함께 생성)
  - asset_dir은 추측 불가 토큰, gitignore 처리
  - 보관 `STUDIO_KEEP_DAYS`(기본 7일), 새벽 정리 작업에서 행·폴더 삭제
  - 현재 로컬 static 저장. S3 이전은 미구현 계획
- 분할 모델: `backend/ml_assets/` (첫 사용 때 자동 다운로드, gitignore)
- 개발용 `STUDIO_DEBUG=true`: 원본 사진·AI 원본 결과를 `backend/studio_debug/{asset_dir}/`에 PNG로 저장 (static 밖, gitignore, 자동 정리 없음)
  - 과거 문서에 있던 `scripts/recompose_render.py`는 현재 저장소에서 확인되지 않아 실행 안내에서 제외함. `compose_bases()`는 기존 AI 출력으로 후처리를 재사용할 수 있는 함수지만 해당 CLI가 제공되는 것은 아님
  - 합성 조정을 AI 재호출 없이 하기 위함, 배포 시 false

## 스키마 참고 — 과거 수동 설치 기록

아래 SQL은 과거 테이블 구조를 설명하기 위해 보존한다. 현재 설치·변경은 [Alembic 설정](../backend/alembic.ini)과 기존 마이그레이션을 기준으로 관리하며, 이 문서를 보고 운영 DB에 수동 CREATE/ALTER를 중복 적용하지 않는다. 이번 문서 갱신에서 DB 명령은 실행하지 않았다.

```sql
CREATE TABLE hair_renders (
	id SERIAL NOT NULL,
	user_id INTEGER,
	guest_id UUID,
	run_id INTEGER,
	style_id VARCHAR(50) NOT NULL,
	status VARCHAR(20) NOT NULL,
	error VARCHAR(300),
	asset_dir VARCHAR(64) NOT NULL,
	created_at TIMESTAMP WITH TIME ZONE DEFAULT now() NOT NULL,
	finished_at TIMESTAMP WITH TIME ZONE,
	hair_hex VARCHAR(7),
	CONSTRAINT pk_hair_renders PRIMARY KEY (id),
	CONSTRAINT fk_hair_renders_run_id_hair_rec_runs FOREIGN KEY(run_id) REFERENCES hair_rec_runs (id) ON DELETE SET NULL,
	CONSTRAINT fk_hair_renders_style_id_hair_style_catalog FOREIGN KEY(style_id) REFERENCES hair_style_catalog (style_id),
	CONSTRAINT uq_hair_renders_asset_dir UNIQUE (asset_dir)
);
CREATE INDEX ix_hair_renders_created_at ON hair_renders (created_at);
CREATE INDEX ix_hair_renders_guest_id ON hair_renders (guest_id);
CREATE INDEX ix_hair_renders_user_id ON hair_renders (user_id);
```

이미 테이블이 있으면 칼럼만 추가

```sql
ALTER TABLE hair_renders ADD COLUMN IF NOT EXISTS hair_hex VARCHAR(7);
```

Alembic 마이그레이션: `f1a2b3c4d5e6_create_hair_renders`, `a7b8c9d0e1f2_add_hair_render_light_base`, `b2c3d4e5f6a7_drop_hair_render_light_state` (스튜디오 스키마의 변경 이력)

## 알려진 한계

- 프리셋은 사진 1장·스타일 몇 개로 맞춘 값, 다른 피부톤·조명·남성 숏컷 검증 필요
- 파스텔 계열은 밝은 베이스라 숱 적은 앞머리에 틈이 살짝 보일 수 있음
- 프리셋 tex·vari는 베이지 light 시절 값, 색은 자동으로 맞지만 명암·결 느낌은 펄 기준 재확인 필요
- 밝은 베이스 앞머리 가닥 끝(눈썹 높이) 몇 px는 이마 구간 밖이라 연하게 남을 수 있음, 머리색과 비슷한 눈썹 가장자리는 살짝 물들 수 있음
- 염색 마스크가 저해상도(256×256) 분할 결과라 비치는 앞머리는 가닥 사이 피부까지 칠해짐 (어두운 색에서 떡져 보임)
- AI가 앞머리를 시스루로 그리는 경우 있음 (카탈로그 사진이 약 90×110px 썸네일이라 디테일 전달 부족, 원본 사진 다시 받기 필요). 현재 눈썹은 원본을 우선하고 머리가 덮는 경우 등에 예외 적용
- 외부 AI(Google)로 얼굴 사진 전송 → 약관 항목 추가 필요


## 현재 운영 범위와 남은 작업

- 결과 보관은 기본 7일이며 회원의 합성 결과도 대상. 업로드 원본 미보관과 생성된 얼굴 이미지 미보관은 다른 의미다.
- 상태 API는 소유자를 검사하지만 static 파일 URL 자체에는 같은 회원 검사가 붙지 않는다. 무작위 경로는 접근 제어와 구분한다.
- `run_id`는 현재 존재 여부만 검사한다. 비회원 결과 이관과 회원 이력 목록에는 HairRender가 포함되지 않는다.
- `BackgroundTasks`는 서버 프로세스 안에서 실행한다. 영속 큐·재시작 후 pending 복구·서버 작업 취소 API는 없다.
- 일반 정리는 결과 행·폴더를 처리하지만 `studio_debug` 원본·진단 파일은 자동 정리하지 않는다.
- 구도·각도 검사는 스타일 재현 정확도나 다양한 사용자 사진의 품질을 보장하는 검사가 아니다.
