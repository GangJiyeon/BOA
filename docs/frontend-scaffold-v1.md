# 중간발표용 프런트엔드 구조 · v2 검수 반영

## 기준과 범위

2026-10-05 통합 커밋 `88fb279`에서 분기한 `codex/frontend-scaffold` 작업이다. 팀 통합 브랜치와 main은 수정하지 않는다. 백엔드·DB 마이그레이션·추천 규칙도 바꾸지 않는다.

꾸미기 전 입력 폼 → API 요청 → 로딩·오류·빈 결과·실제 결과의 연결을 확인하는 구조다. 화면은 해시 주소로 나누고 별도 라우터 패키지를 추가하지 않았다. 분석 결과와 QR 토큰은 메모리에만 보관한다. 새로고침하면 화면의 최근 결과는 사라지지만 서버에서 받은 분석 번호로 다시 조회할 수 있다. 인증은 서버의 HttpOnly 쿠키를 사용한다.

## 화면과 API

| 화면 | 폼·동작 | 백엔드 |
| --- | --- | --- |
| 시작·계정 | 현재 사용자 판별, 촬영 동의, 비회원 시작 | GET `/actor`, GET `/terms/current`, POST `/guest/session` |
| 이메일 로그인·가입 | 이메일 코드 요청·확인, 가입 정보·약관 id 제출 | POST `/auth/email/send`, `/auth/email/verify`, `/auth/signup` |
| 내 계정 | 회원 조회, 언어 저장, 세션 갱신·로그아웃 | GET·PATCH `/me`, POST `/auth/refresh`, `/auth/logout` |
| 피부·화장품 | 사진·선택 수분값 → 분석 scores → 추천 | POST `/skin/analyses/debug` (multipart), POST `/cosmetics/recommendations/preview` |
| 얼굴형·헤어 | 사진 1장 또는 3장, 스타일 구분, 길이·질감 → 얼굴 분석 → 추천 | GET `/hair/styles`, POST `/hair/face-analysis/photos` (multipart), POST `/hair/recommend` |
| 결과 확인 | 이번 실행의 요약, QR 토큰 조회·회원 이관, 분석 번호 조회 | GET `/qr/{token}`, POST `/qr/{token}/claim`, GET `/skin/analyses/{id}`, GET `/hair/recommend/{id}` |
| 키오스크 | 관리자 코드로 기기 등록·해제, 촬영 동의, 사용자 시작·종료 | POST `/kiosk/register`, `/kiosk/revoke`, GET `/kiosk/me`, POST·DELETE `/kiosk/session` |
| AI Studio | 준비 상태와 비활성 버튼 | 현재 연결할 생성 API 없음 |

`src/api/`는 요청·응답 타입과 API 호출, `src/pages/`는 화면 폼, `src/hooks/`는 요청 취소·약관 조회, `src/components/`는 기존 화장품 결과와 공통 표시를 담당한다. `HomePage.tsx`는 메뉴·연결 상태·현재 실행 결과를 관리한다.

## 이번 수정에서 해결한 연결 문제

- API 클라이언트가 `204 No Content`를 JSON으로 읽던 오류를 수정했다. 로그아웃, 인증 갱신, 키오스크 종료를 정상 처리한다.
- FormData의 Content-Type은 브라우저가 작성한다. JSON 요청은 기존 동작을 유지하고 same-origin 쿠키를 전송한다.
- Vite의 `/static` 프록시를 추가했다. `/static/hair/F001.jpg` 같은 헤어 이미지가 프런트엔드 포트에서도 로드된다. 배포할 때에도 `/api`와 `/static`을 백엔드로 넘겨야 한다. Vite 개발 프록시는 배포 설정을 대신하지 않는다.
- 헤어 폼은 사진을 정확히 1장 또는 3장만 허용한다. 길이·질감 선택지는 실제 카탈로그에서 구성한다. 추천 요청만 실패한 경우 같은 사진·스타일 구분에 대해 얼굴 분석을 중복 생성하지 않고 재시도한다.
- 피부·헤어 메뉴는 한 번 열면 같은 세션에서 사진·입력값·추천 결과를 유지한다. 메뉴 이동 중 실행한 분석도 계속 진행한다. 입력 변경 시에는 해당 입력의 이전 결과를 지우며, 로그아웃·키오스크 사용자 종료·새 세션 시작 시 진행 요청을 취소하고 사진·입력·추천·요약·결과 토큰을 함께 초기화한다.
- 기존 피부 점수 의미와 화장품 추천 규칙은 그대로 사용한다. 사진 수분 미측정 등으로 추천이 비어 있는 경우 실제 빈 결과 설명을 표시한다.

## 실제 통합에서 남은 부분

1. 피부 사진 분석과 헤어 분석·추천 라우트에 actor 기반 user_id/guest_id 저장 및 횟수 제한을 연결해야 한다. 현재 프런트는 임의의 사용자 번호를 넣지 않는다. 계정·비회원 세션을 시작했다고 사진 분석 결과가 자동으로 그 세션에 귀속되는 상태는 아니다. 화면의 잔여 횟수는 조회값이며 분석 라우트가 아직 차감·제한하지 않는다.
2. QR 조회의 헤어 결과는 백엔드가 아직 채우지 않는다. 피부 분석도 위 세션 귀속 연결이 없어 QR이 비어 있을 수 있다. 이번 실행 결과 요약은 메모리에서 보여 주며 회원의 전체 분석 이력 기능은 아니다. 결과 공유 주소는 제공하지만 QR 이미지 생성기는 이번 범위에 없다.
3. 현재 약관 API는 종류·버전·필수 여부만 제공한다. 공식 약관 본문을 프런트에 추가해야 한다. 지금은 연결 확인용 체크 항목임을 화면에 표시한다.
4. 이메일 전송 서비스는 SMTP 발송 대신 서버 로그에 인증 코드를 기록한다. 실제 이메일 수신은 아직 테스트할 수 없다. 개발 코드가 API 응답에 포함되는 환경이면 화면에 표시하며, 프런트가 개발 로그인을 자동 활성화하지 않는다.
5. Google 로그인은 백엔드 인가 코드 교환 API만 있다. OAuth 프런트 연결 전까지 버튼을 비활성화했다. AI Studio도 생성 API 없이 임의 결과를 보여 주지 않는다.
6. 쿠키 갱신은 시작·계정 화면의 세션 갱신 버튼으로 확인한다. 자동 401 재시도, 다국어 문구, 사진 미리보기·카메라 촬영, 회원 동의 변경·삭제 등은 후속 UI 작업이다.

## 로컬 적용·실행

오늘 통합본을 커밋하고 작업 트리가 정리된 상태에서 별도 브랜치를 만든다. 아래 패치는 `88fb279` 기준이므로 다른 버전에서는 먼저 `git apply --check` 결과를 확인한다. 압축된 DB나 환경 비밀값을 포함하지 않는다.

다른 터미널에서는 현재 백엔드가 실행 중이어야 한다. 프런트는 `http://localhost:5173`, API는 `http://localhost:8000`을 사용한다. 사용자 PC에서 이미 마이그레이션을 head까지 적용했다면 다시 DB를 변경할 필요는 없다.

발표용 백엔드 버전과 DB 구성을 고정한다. 약관·헤어 카탈로그가 없으면 화면에서 준비 상태를 확인하고, 이번 프런트엔드 패치를 적용하면서 마이그레이션·시드·데이터 가져오기를 실행하지 않는다.

## 발표 전 확인 순서

1. 상단 API·DB 연결 상태 확인. 실패 시 연결 다시 확인 버튼과 백엔드 실행 상태 확인.
2. 시작 화면에서 FACE_IMAGE 약관을 조회하고 촬영 동의·나이 확인 후 비회원 시작.
3. 피부 메뉴에서 실제 얼굴 사진 업로드. 수분 미측정이면 비워 두고 분석 점수와 빈 추천 설명 확인. 측정값 입력 시 추천 결과 확인. 얼굴 미검출 오류와 재시도 확인.
4. 헤어 메뉴에서 1장 또는 3장 업로드, 카탈로그의 길이·질감 선택. 얼굴형·추천·이미지 표시 확인. 사진 2장 입력 시 API 호출 전 거부되는지 확인.
5. 결과 메뉴에서 이번 실행 요약과 번호 조회 확인. QR에는 현재 연결 제한을 설명하고 빈 결과를 성공적인 추천으로 소개하지 않기.
6. 이메일 로그인은 서버 로그/개발 응답에서 코드를 확인할 수 있는 테스트 환경으로 검증. 가입·언어 저장·세션 갱신·로그아웃 확인.
7. ADMIN_CODE를 설정한 테스트 환경에서 키오스크 등록·사용자 시작·종료 확인. 종료 후 이전 사람의 화면 결과가 남지 않는지 확인.

## 이 작업 환경에서의 검증

- TypeScript·Vite 빌드 통과, oxlint 경고·오류 없음.
- API 클라이언트 16개 확인 통과: JSON, multipart, 오류 메시지, AbortSignal, 쿠키 옵션, 본문 없는 204 처리, JSON이 아닌 오류·성공 응답, 네트워크 실패, 취소 오류 전달.
- 브라우저에서 피부·화장품, 헤어의 실제 FastAPI 라우트와 테스트 SQLite DB로 사진 업로드 → 저장 → 추천 → 결과·이미지 표시를 확인했다. CV 분석 함수는 테스트 대역으로 바꿨다. 실제 사진의 얼굴 인식 정확도·MediaPipe 실행·실제 PostgreSQL 저장은 이 브라우저 검증의 대상이 아니다.
- 계정·비회원·QR·키오스크 응답은 브라우저 테스트에서 대체했다. 폼 요청값, 동의 전 버튼 비활성화, 가입 단계, 204 응답, 결과 초기화, 빈 QR, 키오스크 시작·종료를 확인했으며 실제 인증·발송·쿠키 저장·세션 귀속을 검증한 것은 아니다.
- 390px 모바일에서 가로 넘침 없음, 브라우저 JavaScript 예외 없음.

저장소 업데이트는 이 별도 브랜치를 커밋·push해서 진행한다. 오늘 팀 최종 머지에는 포함하지 않는다.
