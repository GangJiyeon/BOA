# 메이크업 표현과 변경 기록

현행화: 2026-11-15, 현재 로컬 코드 기준. 아래 현재 동작과 접힌 과거 실험 기록을 구분한다. 외부 참고 링크는 당시 자료를 보존한 것이며 이번 갱신에서 내용을 재검증하지 않았다.

## 현재 동작

- [MakeupPage](../frontend/src/pages/MakeupPage.tsx)에서 사진을 올리면 피부톤 API로 웜·뉴트럴·쿨과 밝기·쿠션 정보를 받는다. 직접 선택한 값이 있으면 분석 응답으로 덮어쓰지 않는다. 현재 선택 체계는 봄·여름·가을·겨울 4계절 UI가 아니다.
- 사진의 얼굴 좌표·얼굴형·코·광대·눈썹 제거 이미지는 [메이크업 전처리 API](../backend/app/api/routes/makeup.py)에서 준비한다. 얼굴 사진을 외부 생성형 AI로 보내는 헤어 합성과 달리 메이크업은 로컬 전처리와 브라우저 렌더링이다.
- [MakeupStudio](../frontend/src/components/MakeupStudio.tsx)는 [Worker](../frontend/src/studio/makeup-worker.ts)에서 얼굴 마스크와 픽셀을 계산하고, 메인 화면에서 Canvas·눈썹·속눈썹을 조합한다. Worker와 미리보기 경로는 현재 사용 중이다.
- 팔레트·성별·상황별 조합은 [makeup-looks.ts](../frontend/src/studio/makeup-looks.ts)의 현재 레시피가 기준이다. 눈 음영에는 브라운 외에 일부 피치·핑크도 있어 과거의 ‘모든 눈 색은 브라운’ 설명을 현재 전체 동작으로 적용하지 않는다.
- 아이라인 선택지는 basic/wing/down 세 종류다. 과거 softDown/winter/defined/short에 관한 설명은 아래 실험 기록이며 현재 선택지를 뜻하지 않는다.
- 블러셔는 상황·룩·성별별 개별 강도와 위치를 사용한다. 모든 룩에 공통 36/48/60/72/84%나 10~44%를 적용하는 상태가 아니다. 현재 레시피에는 이보다 강한 값도 있다.
- 여성 눈 화장의 배율·사진별 눈매 보정, 창백한 입술의 색·강도 보정은 별도 로직이다. 실제 값을 문서에 중복 나열하기보다 레시피와 보정 상수를 기준으로 확인한다.
- 립은 그라데이션·블러 등 표현과 광택을 조합한다. 반사광 추정은 기존 사진 픽셀에 의존하며 하얗게 날아간 디테일을 복원하지 않는다.
- 사용자 조절은 사진의 가상 표현이며 실제 제품 발색·퍼스널컬러 진단 정확도를 보증하지 않는다.

## 에셋과 유지할 데이터

눈썹·속눈썹은 각 `catalog.json`이 생성된 PNG를 동적으로 참조한다. 파일명을 소스에서 직접 찾을 수 없다는 이유로 삭제하지 않는다. 원본 PNG 폴더는 다음 생성 스크립트의 입력이다.

- [눈썹 생성 스크립트](../backend/scripts/prepare_brow_assets.py): brows·eyebrows-face-shapes-6·brows-v2·brows-male 원본을 사용.
- [속눈썹 생성 스크립트](../backend/scripts/prepare_lash_assets.py): lashes-src 원본을 사용.

2026-11-15 정적 대조에서는 눈썹 18종의 생성 PNG 54개, 속눈썹 5종의 생성 PNG 19개가 카탈로그에 연결됐고 누락 파일은 없었다. 현재 파일 기준 결과이며 일반화된 자동 검증 보장은 아니다.

## 계산에 반영되지 않는 기존 필드

`brow_regions`는 서버에서 생성해 응답하고 프론트에서 크롭 좌표로 변환하지만, [browPlacement()](../frontend/src/studio/brows.ts)의 `_region` 인자는 현재 사용하지 않는다. 실제 배치는 얼굴 랜드마크를 기준으로 한다. 응답·변환·타입·테스트는 이번 문서 작업에서 제거하지 않았다.

Worker의 ‘browReplacementFace와 같은 계산’ 주석은 현재 없는 함수명을 가리킨다. 실제 눈썹 제거 이미지 혼합은 Worker 안의 `withBrowBase()`에서 수행한다. 이 주석 때문에 눈썹 제거 이미지 자체가 미사용이라고 해석하면 안 된다.

### 셀럽 눈 화장 형태 참고 (2026-11-09)

최신 유행 하나로 통일하지 않고 맑은 눈·가로 확장·스머지의 세 방향을 구분했다. 강도 배율과 색은 유지하고, 높은 다각형 채움은 속눈썹 가까운 그라데이션으로 바꾼다. 아이라인은 안쪽을 얇게, 바깥쪽을 또렷하게 하며 꼬리를 급격히 올리지 않는다. 언더 음영은 바깥 1/3에 한정한다. 이는 자료를 참고한 앱 구현 방향이며 특정 셀럽의 메이크업을 재현했다는 의미는 아니다.

### 로컬 참고 사진의 아이라인 재조정 (2026-11-11)

`backend/static/makeup/demo`의 스크린샷을 시간순으로 대응한다.

1. 19:30:40: 눈 바깥쪽부터 두꺼워지고 아래로 길게 빠지는 꼬리 (`softDown`). 눈 중앙에 둥근 덩어리를 더하지 않는다.
2. 19:31:00: 앞라인은 얇고, 눈축을 따라 거의 일자로 길게 빠지는 꼬리 (`winter`). 위로 꺾어 올리지 않는다.
3. 19:31:16: 바깥 1/3과 꼬리를 도톰하게 강조 (`defined`). 과도한 상승 각도를 피한다.
4. 19:31:32: 얇은 윗라인과 짧게 이어지는 꼬리 (`short`).

꼬리는 위·아래 두 경계를 함께 그려 속눈썹에서 끊김 없이 끝점으로 모은다. 두께 방향은 눈축의 수직 방향으로 계산한다. 추천 이름은 색상과 강조 부위를 표시하며 이전의 동물·인형식 별칭은 제거했다. 사진 속 언더 속눈썹·펄·눈 모양 자체의 변화는 아이라인 마스크에 포함하지 않는다.

### 최종 단순화

이후 피드백으로 위 참고 사진 기반의 긴 꼬리·강조형 선택지는 제거했다. 현재 노출·추천·마스크 모두 `basic`(기본 라인), `wing`(짧은 일자 꼬리), `down`(살짝 내린 꼬리) 3종만 사용한다. 꼬리는 눈 너비의 10~12%로 짧게 제한하며, 기존 색상·발색 강도는 유지한다. 추천 룩의 차이는 블러셔·섀도우·립 구성으로 유지한다.

### 원본 입술 광택에 따른 마감

입술 내부의 주변 명도와 비교해 국소적인 반사광을 분리한다. 매트립은 분리한 반사광을 낮추고, 촉촉립은 원본 광택이 많을수록 추가 하이라이트를 줄인다. 밝은 입술 전체를 반사광으로 판단하지 않으며, 효과 0에서는 원본을 보존한다. 색상 강도와 별도로 마감 계산을 하되 같은 립 강도에 따라 부드럽게 반영한다. 픽셀 기반 추정이므로 이미 하얗게 날아간 입술 디테일을 복원하는 기능은 아니다.

### 블러셔·섀도우 발색 강화

사용자가 제공한 Makeup looks JSON의 상황별 강도 1~5단계를 참고했다. 4계절 모두 동일한 단계 배열이므로 상황별 배열을 공통 적용한다. 블러셔는 단계별 기본값 36/48/60/72/84%, 섀도우는 32/45/60/78/95%를 기준으로 기존 강조 룩의 더 높은 강도는 유지한다.

블러셔의 피부 혼합 비율을 0.6에서 0.85로 높이고 색상 반영도도 올렸다. 섀도우는 기존의 빠른 강도 포화를 완만한 곡선으로 바꿔 높은 단계에서도 차이가 나도록 한다. 참고 JSON의 펄·글리터·추가 아이라인 형태를 새로 구현한 것은 아니며, 기존 뉴트럴 눈 색상과 아이라인 3종은 유지한다.

### 블러셔 영역·립 표현 재구성

후속 피드백에 따라 블러셔의 공통 최소 강도와 눈 화장 단계 연동을 제거했다. 추천 농도는 상황·룩별 10~44%로 나누고, 중앙의 작은 원형 / 넓고 옅은 볼 / 사선 / 눈 밑 가로 네 가지 영역을 조합한다. 넓은 영역은 더 낮은 농도로 사용한다. 섀도우 강도는 유지한다.

그라데이션 립은 입술 안쪽의 발색을 유지하며 가장자리 마스크를 더 빠르게 줄인다. 경계를 부드럽게 채우는 블러립도 추가했다. 화면에서 블러셔 위치와 립 표현을 직접 선택할 수 있으며, 룩 변경 시 해당 룩의 기본값으로 돌아간다.
