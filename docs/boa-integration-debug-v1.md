# 피부 분석 → 화장품 추천 통합 디버깅

기준 원격: feature/cosmetic-recommendation 7a86af9. 최신 main ea0518f 포함.

## 수정

- 기본 화면을 사진 분석 후 자동 추천으로 변경. 기존 POST /api/skin/analyses/debug에 사진을 FormData로 전달하고 응답 scores 배열을 그대로 POST /api/cosmetics/recommendations/preview에 전달한다.
- 수분은 미측정(None)이 기본. 직접 입력은 센서 통합 전 개발용이며 0~100 정수 검증. 사진에서 수분을 추정하지 않는다.
- 분석 경로에서 점수는 DB에 저장되며 원본 사진은 저장되지 않는다는 설명으로 수정. 추천 요청 자체는 조회 전용.
- 파일 업로드에서는 Content-Type 헤더를 브라우저에 맡겨 multipart boundary 오류를 방지한다.
- 피부 API의 detail.message를 화면에 표시한다. 기존 문자열/검증 배열 오류도 유지한다.
- 입력 변경 시 진행 중인 요청을 취소해 이전 결과가 새 조건에 나타나는 것을 방지한다.
- 추천 단계 실패 시 동일 파일·수분값의 이미 완료한 분석을 재사용한다. 재시도/추천 필터 변경으로 분석을 중복 저장하지 않는다. 파일이나 수분을 바꾸면 새 분석을 수행한다. 새로고침 후에는 메모리 캐시를 유지하지 않는다.

## 확인

- 백엔드 테스트159개(기존154+통합5): 사진 분석 API → 저장/라벨링 → 실제 추천 API 호출, 수분 포함/미측정, 손상 사진 실제 디코딩 실패, 얼굴 검출 오류, 앱 lifespan 시작/종료.
- 정상 사진 결과는 테스트 대역으로 고정하여 API 전달·저장을 검증했다. 실제 사진의 CV 정확도는 검증하지 않았다.
- 브라우저에서 실제 프런트와 테스트 API/SQLite로 업로드 → 분석 저장 → 자동 추천 확인. 정상 CV만 테스트 대역. 추천 503 후 재시도 시 분석 호출1회/추천2회; 얼굴 검출 실패 때 상세 오류 표시/이전 카드 제거/추천 요청 미실행. JavaScript 예외 없음.
- API 공통 함수 테스트8개: JSON/파일 헤더, 취소 신호 전달, 피부 API 구조화 오류, 기존 오류 형식.
- 프런트 TypeScript/Vite 빌드와 oxlint 통과.

## 남은 통합

이 경로는 팀의 기존 debug 사진 분석 API를 사용하는 S3 없는 통합 확인 경로다. 정식 키오스크/회원 실행 경로는 아직 완성되지 않았다.

- skin/hair 분석 API에 새 get_actor/require_analysis_actor 및 quota 사용이 연결되지 않았다. 피부 분석 debug 경로는 결과 user_id/guest_id 없이 저장한다. 회원 귀속·촬영 동의·할당량 처리가 필요하다.
- S3 없는 일반 /skin/analyses는 현재 더미 점수를 생성할 수 있다. 사진을 실제 분석하는 이번 경로와 구분한다.
- 센서/BLE 입력을 이 화면의 수분 입력으로 연결하지 않았다.
- 사용자 PostgreSQL의 alembic current와 실제 사진의 분석 거부/추천 결과는 사용자 환경에서 확인해야 한다. 코드 head는 ae596f5070ae. heads는 DB 적용 확인이 아니다.
- 기존 계정 마이그레이션은 legacy 단수형 테이블에 DROP TABLE ... CASCADE를 실행하므로 DB 백업/현재 스키마 확인 없이 upgrade를 실행하지 않는다.
- 밝기/균일도/트러블 매칭은 앞선 photo_v1 정책대로 보류한다. 실제 점수에 임의 성분 효능을 붙이지 않는다.

DB 스키마 변경 및 DB 적용 명령은 이 패치에 없다. 정상 흐름을 테스트 환경에서 확인했으나 전체 프로젝트/센서/계정 기능 완료를 의미하지 않는다.
