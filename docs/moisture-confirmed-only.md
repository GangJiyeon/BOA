# 측정 확정과 신호 부족 종료 처리 통합

## 완료한 범위와 미완료 범위
본 수정은 신호가 부족한 자료를 성공 숫자로 보여주던 잘못된 완료 처리를 끝낸다. 기존 20% 분해능 기준이나 물리식을 새로 조정한 것이 아니다. 정확한 피부 수분 함량 및 검증된 부족/보통/충분 판정 모델을 완성한 수정은 아니다. 센서 주파수 분주비 조정도 포함하지 않는다.

## 사용자 흐름
- 1회 피부 접촉에서 안정화와 3초 표본 수집.
- 조건을 통과한 결과만 완료 숫자를 표시하고 사진 분석에 연결 저장하며 기존 실험적 추천 보조 입력으로 전달.
- 출력 분해능에 비해 반응이 작은 경우에는 '측정 신호가 부족해 결과를 확정하지 못했습니다'로 종료. 대표 숫자는 대시로 표시. 성공 콜백/완료음/완료 결과 저장/추천 전달을 실행하지 않음.
- 경고/접촉 해제/큰 불안정/시간 초과 역시 성공으로 처리하지 않음.
- 성공과 실패 모두 해당 시도를 끝내고 유지. 센서를 떼었다 다시 대는 것만으로 자동 재시작하지 않음. 사용자가 '다시 측정'을 눌렀을 때만 보정과 새 시도를 시작.
- 거부한 약한 구간의 원시 자료는 전체 진단 기록에 measurement_rejected 이벤트로 보존. 성공 측정 결과와 구분. 실패 후에도 최대30초 진단 수신만 유지.
- 서버는 새 알고리즘의 약한 결과 업로드를422로 거부하고 DB에 성공 결과로 저장하지 않음. 이미 저장된 옛 v3/v4 자료는 소급 삭제하지 않음. 기존 분해능 제한 기록은 화면에서 성공 숫자 대신 '확정 불가'로 표시.
- 새 수락 정책은 내부 algorithm_version=skin-auto-v5로 구분. 이전 자료의 계산 의미를 유지하기 위한 구분이며 새 임상 보정식이 아님.

## 검증
- 사용자가 준 첫 로그를 재생: 기존 완료 지점은 대기. 동일한 약한 마지막 값이 유지된다는 가상 연장에서도 최종 성공 콜백 없이 거부.
- 사용자가 준 두 번째 전체 로그를 재생: 성공 콜백0회, 결과null, 거부 이벤트1회. 이후 센서를 뗀 기록이 들어와도 추가 성공/자동 재시작 없음.
- React 실제 화면 조작: 신호 부족 시 큰 숫자는 대시, '자동 측정 완료' 없음, 다시 측정 버튼 제공. 명시적 재시작 뒤 유효 모의 신호는 한 번 완료.
- 서버43개 테스트: 약한 새 결과422 및 분석 관측 미저장, 유효 모의 결과 저장·추천 보조 연결, 기존 경로 회귀 통과.
- 프론트 자동측정/DOM/TypeScript/Vite 빌드 통과.
- 실제 장치 재시험과 피부 수분 정확도 검증은 수행하지 못함. 재생/모의 테스트는 장치 정확도 검증을 대체하지 않음.

## 적용
현재 BOA-moisture-quality-fix 또는 BOA-single-contact-response 적용 상태에 frontend/backend/docs를 프로젝트 루트 기준으로 덮어쓴다. 프론트와 백엔드를 함께 적용한다. DB 마이그레이션과 Arduino 재업로드는 없다.

백엔드 PowerShell:
cd C:\Users\USER\Desktop\BOA-git\backend
docker compose restart api

새 터미널 프론트:
cd C:\Users\USER\Desktop\BOA-git\frontend
npm run dev

브라우저를 새로고침한다. 코드를 Docker 이미지에 포함해 실행하는 구성은 restart 대신 docker compose up -d --build api로 반영한다.

실패했다고 세게 눌러 통과시키지 않는다. '신호 부족'은 건조 판정도 아니고 사용자가 잘못 접촉했다는 판정도 아니다. 이 장비와 설정에서 신뢰할 수 있는 수분 결과를 확정하지 못했다는 의미다.

## 테스트 자료
두 제공 로그에서 측정ID, 원래 날짜, 이벤트 메타데이터를 제거하고 기술적인 수신 표본만 남긴 회귀 fixture를 포함한다. 외부 공개/전송이나 Git 커밋은 수행하지 않았다.
