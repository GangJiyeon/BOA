# 동일 정렬 조건 제품 더보기

## 변경 범위

최초 조회는 기존처럼 상위 5개다. 화면은 같은 정렬 조건의 후보를 묶어 표시하며, 각 묶음에서 5개씩 더 조회할 수 있다. 마지막 페이지는 남은 수만 반환한다. 더보기로 낮은 정렬 조건의 묶음까지 넘어가지 않는다.

동점은 선택한 정책의 모든 정렬 조건이 동일하다는 뜻이다. 매칭 지표 또는 고민 그룹 수뿐 아니라 우선 고민 매칭 여부(해당 정책)와 세트 의심 여부도 포함한다. 성분 조합이나 제품 효능이 동일하다는 뜻은 아니다. ID는 재현 가능한 내부 조회 순서로 유지하며 화면의 순위 번호와 ID 정렬 안내는 제거했다.

성분 수·함량·임의 가중치를 새 점수로 도입하지 않았다. 동점 안의 우열을 정하는 작업은 추가 근거와 검증이 필요하다. 얼굴용 후보 필터는 유지한다. 제품 카드의 사용법 미확인 문구와 상세 제한의 중복 문구는 제거하되, 내부 `usage_mode`, `usage_basis`는 유지한다.

## API

`POST /api/cosmetics/recommendations/preview`

최초 요청에는 기존 입력을 사용한다. 응답에 `snapshot_token`, `tie_groups`가 추가되며, 제품마다 `ranking_group`을 제공한다.

각 그룹의 `key`, `total`, `next_offset`으로 추가 조회한다. 같은 최초 입력에 `tie_group`, `tie_offset`, `snapshot_token`을 함께 전송한다. `next_offset: null`이면 마지막 페이지다. 매번 최대 5개를 반환하며 응답의 그룹 메타데이터는 이번 조회 그룹에 해당한다.

토큰은 입력, 엔진·정렬 정책 버전, 규칙, 판정 기준, 정렬된 전체 후보 내용과 집계에서 계산한다. 조건이나 결과 데이터가 달라지면 HTTP 409로 재조회를 안내한다. 잘못된 그룹·위치·요청은 422다. 토큰은 인증 수단이 아니다. 조회마다 DB를 읽어 재계산하며 서버에 결과를 저장하지 않는다.

화면은 최초 입력으로 더보기를 요청하고, 입력 변경 시 더보기 요청을 취소한다. 중복 클릭은 막으며 네트워크 실패 시 기존 목록을 보존한다. 409 이후에는 더보기를 막고 다시 추천 조회하도록 안내한다.

## 검증

- 로컬 전체 단위/API 테스트 154개 통과. 새 테스트 10개 포함.
- 사용자의 이전 136개 구성에 이 패치만 추가하면 146개가 예상된다. 로컬의 별도 정책 비교 테스트 8개는 이 패치에 포함하지 않았다.
- 원본 SQLite 2,584개 제품에서 사용자 예시(수분 0, 홍조 50, 밝기 0, 트러블 100, 균일도 100)를 재현했다. 동점 31개를 5/5/5/5/5/5/1개로 조회했고 중복 없이 모두 표시할 응답을 얻었다.
- 기존 실제 제품 기준 사례 15/15 통과. 프런트엔드 build/lint 통과.
- 사용자 PC의 PostgreSQL과 브라우저 클릭 동작은 직접 검증하지 않았다.

## 적용

저장소 루트에서 패치를 적용하고 backend 테스트와 frontend build/lint를 실행한다. 스키마·시드·기존 데이터 변경은 없으며 Alembic 명령은 필요 없다. API와 프런트엔드를 함께 갱신해야 한다.
