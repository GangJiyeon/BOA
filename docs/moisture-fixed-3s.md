# 피부 수분 측정 — 고정3초·BOA 점수 연결

## 적용

이 ZIP 하나를 현재 BOA 프로젝트 루트에 덮어쓴다. 이전 패치를 따로 순서대로 적용할 필요는 없다. 현재 사용 중인 Arduino 펌웨어와 BLE 프로토콜은 유지한다. **아두이노 재업로드와 DB 마이그레이션은 필요 없다.**

백엔드 반영:

```powershell
cd C:\Users\USER\Desktop\BOA-git\backend
docker compose up -d --build api
```

프론트엔드 실행:

```powershell
cd C:\Users\USER\Desktop\BOA-git\frontend
npm run dev
```

브라우저를 새로고침하고 측정기를 연결한다. 기준값 보정은 센서 면을 피부에서 뗀 상태에서 실행한다. 준비 안내 후 피부에 한 번 대면3초 측정하고 끝난다.

## 동작

1. 공기 기준과 잡음을 확인한 뒤 접촉 신호를 감지한다.
2. 접촉 감지 즉시3,000ms 수집을 시작한다. 후보 확인300ms, 추가 안정화1초, 변동에 따른 연장, 최대10초 대기를 제거했다.
3. 3초 창을 닫고 그 뒤 도착하는 표본을 계산에 추가하지 않는다. 브라우저 타이머가 창을 종료하며 다음 BLE 패킷을 기다리지 않는다. 화면 갱신은 일반 브라우저 스케줄링을 따른다.
4. 전체3초는 기록하고, 접촉 초반의 변화에 덜 영향을 받도록 마지막1초의 원시값 중앙값으로 점수를 산출한다. 변화량이 크다는 이유만으로 측정을 연장하거나 실패시키지 않는다.
5. 완료 후 같은 결과를 유지한다. 계속 접촉하거나 떼었다가 다시 대도 자동으로 재측정하지 않는다. 완료 뒤의 진단 표본 수집도 중단했다.
6. 통신 단절, 센서 오류, 피부를 뗀 상태, 유효 표본 부족은 오류로 처리한다. 없는 센서 데이터를 숫자로 만들어 내지 않는다.

## 점수 정의와 범위

현재 점수는 **BOA의 센서 상대 점수1~100**이다. 피부에 포함된 물의 질량·부피 백분율이나 Corneometer AU가 아니다.

FDC2112의 기존 설정인 gain16/offset170에서 공기 기준 B와 마지막1초 중앙값 x를 사용한다.

```text
정전용량 증가율 r(%) = 100 × [((B + 170) / (x + 170))² − 1]
BOA 수분 점수 = clamp(round(max(0,r) × 10), 1, 100)
```

**증가율0~10%를 점수 범위로 사용하는 것은 BOA의 초기 공학적 정규화 선택이다. 제조사가 검증한 피부 수분 보정계수나 임상 판정 기준에서 가져온 값이 아니다.** 이 범위로 바꿨다는 사실만으로 피부 수분 측정 정확도가 높아졌다고 주장하지 않는다. 점수를 특정 사람에게40이나50이 나오도록 맞추지 않았고, 기존30-count 범위도 사용하지 않는다.

공기 보정값, 전체 표본, 마지막1초 대표값, 계산식 식별자를 보존한다. 같은 입력에는 프론트와 서버가 같은 정수 점수를 산출한다. 서버가 원시 표본에서 재계산하며 브라우저가 만들어 보낸 점수를 신뢰해서 저장하지 않는다.

## 기존 분석·추천 연결

- 결과를 측정 관측 기록에 저장하고, 기존 `SkinScore`의 `moisture` 점수에도 직접 저장한다. 분석 응답을 다시 조회해도 같은 값이 나온다.
- 기존 DB의 수분 카테고리 경계를 조회해 적용한다. 기본 시드는0~33 개선 필요 /34~66 보통 /67~100 양호다. 이 구간은 프로젝트의 점수 분류이며 새 임상 기준이 아니다. 수분이 높다는 이유로 지성으로 판정하지 않는다.
- 추천에 수분을 포함한 점수 배열을 넘겨 기존 성분 매칭 규칙에 반영한다. 종전의 동점 후보 보조 가중치 경로가 아니다.
- 동일한 측정 ID 재전송은 중복 관측·중복 점수를 만들지 않는다. 다시 측정한 결과는 해당 분석의 기존 수분 점수를 갱신한다.
- 사진 분석 ID가 처음 생기는 순간 진행 중인3초 측정을 초기화하지 않도록 수정했다. 다른 사진으로 바꾸면 이전 측정 연결은 해제한다.

## 화면

기본 화면은 연결·보정 버튼,3초 진행 상태, 큰 수분 점수 `/100`, 완료 표시만 보여준다. 원시값·수식·다운로드는 한 개의 접힌 ‘측정 상세’ 안에 둔다. 실시간 신호의1.5%나2.0%를 최종 결과처럼 크게 표시하지 않는다.

## 확인한 결과

사용자가 올린 최근 로그에서 접촉 감지 시점부터3초만 재생했다.

- 첫 표본: seq818 /84,781ms /2538 counts
- 마지막 포함 표본: seq847 /87,714ms /2505 counts
- 창 종료:87,781ms —3,000ms 고정
- 마지막1초 중앙값:2506 counts /공기 기준2540
- BOA 점수:**26/100**
- 실제 로그 도착 간격으로 재생한 완료 시점은 시작 후3,000.3ms였다. 그 뒤의 표본을 이 결과에 추가하지 않았다.

이는 이미 받은 원시 로그를 새 계산으로 재생한 결과다. 새 코드로 실제 피부를 다시 측정했거나 피부 수분 함량26%가 검증되었다는 의미는 아니다.

통합 검증: 고정3초 타이머, 시간 연장 없음, 단일 완료, 완료 후 기록 중단, 실제 BLE 패킷 경로, 사진 분석 연결, DB 수분 점수 저장·재조회, 사진 분석 추천 모드에서 수분 성분 매칭, 재전송 중복 방지. 백엔드50개 테스트와 프론트 회귀·DOM 통합·빌드를 통과했다.

내부 식별자: `skin-fixed-3s-v1`, `boa-cap-response-10-v1`. 과거 측정 데이터의 의미를 보존하기 위한 식별자이며 사용자 화면에는 노출하지 않는다.
