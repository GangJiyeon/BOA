# 1단계 — 수분 상태별 추천·제외 정책

대상은 현재 작업 중인 BOA 프로젝트다. 이번 업데이트는 **입력된 수분 카테고리를 받아 제품을 선택하는 추천 정책**이다. 센서 원시값을 수분 부족·보통·충분으로 나누는 물리적 경계값을 새로 정하지 않는다. 기존3초 측정과 펌웨어는 변경하지 않는다.

## 적용

ZIP 내용을 프로젝트 루트에 덮어쓴 뒤 다음을 실행한다.

```powershell
cd C:\Users\USER\Desktop\BOA-git\backend
docker compose up -d --build api
docker compose exec api alembic upgrade head
docker compose exec api python scripts/seed_cosmetic_rules.py --apply
```

규칙 버전 `cosmetic-rules-2026-10-28-hydration-v1`, 규칙35개가 출력되는지 확인한다. 같은 시드를 다시 실행하면 `unchanged`다. 기존 규칙 버전과 상품·분석 데이터는 삭제하지 않는다. 신규 규칙에 필요한 성분명·카테고리가 누락되면 시드는 쓰기 전에 중단한다.

프론트엔드 터미널:

```powershell
cd C:\Users\USER\Desktop\BOA-git\frontend
npm run dev
```

브라우저를 새로고침한다. 아두이노를 재업로드할 필요는 없다.

## 구현한 정책

| 입력된 수분 상태 | 제품 선택 | 수분에 따른 제외 |
|---|---|---|
| 개선 필요 → 부족 | 보습·수분 손실 억제 성분 후보. 기존 주요 추천 순위가 같으면 두 기능군을 함께 포함한 제품 우선 | 사용자가 새 옵션을 켰을 때 향료·에탄올·변성알코올 제외 |
| 보통 | 별도의 보습 유지 규칙 사용. 개선 점수 추가 없음 | 자동 배제 없음 |
| 양호 → 충분 | 별도의 유지 관리 규칙 사용. 다른 개선 지표가 있으면 해당 규칙으로 추천 | 높은 수분을 이유로 유분 성분 배제 없음 |
| 미측정 | 수분 상태를 추측하지 않고 일반 관리 후보 탐색 | 수분 부족 조건부 배제 없음 |

부족할 때 활성 보습 후보 성분은 글리세린·판테놀·하이알루로닉애씨드, 수분 손실 억제 후보 성분은 다이메티콘·페트롤라툼이다. 기존 보류 성분인 소듐하이알루로네이트·세라마이드엔피·우레아는 이번에 임의 활성화하지 않았다.

두 기능군을 함께 포함했다고 지표 점수를2점 주지는 않는다. 수분 매칭은 여전히1점이다. 기능군 함유 우선은 기존 지표 수·지정 고민·세트 조건이 동일한 후보 안에서만 적용하는 프로젝트 순위 정책이다. 성분 수나 함유만으로 완제품 효능이 더 높다고 판정하는 것은 아니다.

보통과 충분은 상태·규칙·설명을 구분하지만, 같은 유지용 제품이 추천될 수 있다. 수분이 충분하다는 이유만으로 지성으로 판정하거나 보습 제품을 금지하지 않는다. 크림·젤의 실제 제형을 판정하는 기능은 이번 범위에 포함하지 않는다.

## 화면과 API

기존 ‘성분 제외 조건’ 안에 다음 옵션을 추가했다. 기본값은 꺼짐이다.

`수분 부족이면 향료·에탄올·변성알코올 제외`

API 필드는 `avoid_dryness_triggers`이며, 수분 부족과 옵션 선택이 모두 충족되어야 동작한다. 홍조 옵션과 직접 입력한 제외 성분은 각각 독립적으로 적용한다. 세틸알코올·스테아릴알코올은 새 배제 목록에 포함하지 않는다.

추천 응답에 `hydration_policy`를 추가했다. 버전·입력 상태·추천 방향·옵션 활성 여부를 반환한다. `basis=supplied_moisture_category`는 센서에서 직접 판정한 값이 아니라 전달받은 카테고리를 사용했다는 뜻이다. 화면에는 추천 방향 한 줄만 보여주고, 순위 기준은 접힌 상세에서 확인한다.

## 규칙 저장

- 기존20개 규칙에 부족 성분 매칭2개, 보통·충분 유지 규칙10개, 선택적 제외3개를 추가해 총35개다.
- 유지 규칙은 `effect=maintain`, 점수0이다. 선택적 수분 배제는 `condition=dryness_opt_in`이다.
- Alembic `f0910a1b2c3d`가 이 두 값을 저장할 수 있도록 제약만 확장한다. 이전 버전의 규칙은 그대로 보존한다.
- 신규 규칙 이력이 존재하는 상태에서 이를 잃게 되는 downgrade는 거부한다.
- 규칙의 DB 조회 순서가 달라져도 더보기 결과 토큰이 바뀌지 않도록 정규화된 규칙 지문을 사용한다.

## 검증

추천 관련168개 테스트와 수분 정책·측정 저장 관련30개 테스트가 통과했다. 기존 규칙 보존, 새 규칙 저장·재실행, 선택적 배제, 홍조 옵션과의 독립성, 직접 제외 우선, 기능군 순위, 더보기, 미측정 처리 등을 확인했다. 화면 통합에서 새 옵션이 사진 분석 후 추천 갱신까지 전달됨을 확인했고 프론트 빌드도 통과했다.

첨부된 카탈로그2,584개 제품을 별도 메모리 DB에 복제해 실제 규칙 DB 경로와 오프라인 엔진이 같은 결과를 내는지 확인했다. 원본 파일은 변경하지 않았다. 동일한 다른 지표를 둔 **정책 연동 시험 입력**에서:

| 시험 조건 | 추천 후보 수 |
|---|---:|
| 수분 부족 입력, 새 제외 옵션 끔 | 1,619 |
| 수분 부족 입력, 새 제외 옵션 켬 | 1,136 |
| 보통 입력 | 1,619 |
| 충분 입력, 새 제외 옵션 켬 | 1,619 |

후보 수는 필터·성분 규칙을 통과한 수이며 제품 효능이나 적합성 검증 결과가 아니다. 테스트는 SQLite에서 수행했으며 사용자 PC의 PostgreSQL에는 이 환경에서 접속하거나 변경하지 않았다.

## 근거와 현재 범위

건조 피부의 성분 선택·자극 회피 정책은 아래 AAD 공개 안내를 참고했다. 개별 제품의 농도·제형·안전성이나 센서의 수분 판정 경계를 보증하는 근거로 사용하지 않는다.

https://www.aad.org/public/everyday-care/skin-care-basics/dry/dermatologists-tips-relieve-dry-skin

이번에 완료한 것은 **수분 상태 → 추천·제외** 부분이다. **센서 신호 → 수분 상태 추정** 기준은 다음 작업으로 남아 있다. 기존 점수 구간이나 앞서 만든 임의 환산을 이번 정책의 생체학적 검증 근거로 삼지 않는다.
