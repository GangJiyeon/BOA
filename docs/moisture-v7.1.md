# Moisture v7.1 수정

v7 적용 프로젝트용 프론트엔드 수정입니다. 기존 프로젝트의 frontend 폴더에 덮어쓴 뒤 프론트엔드를 재시작하고 브라우저를 새로고침하세요. Arduino 업로드 및 DB 변경은 필요 없습니다. 기존 moisture_sensor 펌웨어를 그대로 사용합니다.

## 전달 오류 수정
- 센서 측정 → 첫 사진 선택 순서에서 완료 측정값을 삭제하던 문제를 수정했습니다.
- 분석 번호가 생기면 기존 완료값을 해당 분석에 저장합니다.
- 결과 메뉴로 이동해 패널이 숨겨져도 완료값 저장을 계속하고 상위 피부 분석 결과를 갱신합니다.
- 기존 사진 교체/삭제 및 입력 모드 변경 시에는 이전 측정을 초기화합니다. 다른 사진에 이전 값을 잘못 재사용하지 않습니다.
- 실패 시 기존 저장 재시도 버튼을 사용합니다. 새로고침 전 미저장 측정은 메모리에만 있습니다.

## 3% 계산 검토
제조사 원본 moisture_getData 및 현재 펌웨어/프론트/서버가 쓰는 식은 공통적으로 다음과 같습니다.

(공기 중 기준 count - 접촉 count 평균) / 공기 중 기준 count × 100

제조사 원본: https://github.com/MikroElektronika/Moisture_click/blob/master/library/__moisture_driver.c

예시: 공기 506, 평균 490이면 3.1621%; 평균 395이면 21.9368%입니다. 이는 사용자의 이번 측정 원시값을 확인했다는 뜻이 아닙니다. 제조사 예제는 정수 나눗셈을 쓰지만 BOA 완료값은 새 표본 평균으로 계산 후 소수 둘째 자리까지 표시합니다. 실시간 표시도 이번 수정에서 소수 둘째 자리로 통일했습니다.

3%만으로 피부 수분 함량이 3%라고 판정할 수 없습니다. 완료 화면에 공기 기준값, 접촉 평균, 계산식을 표시합니다. 화면 명칭도 센서 신호 변화율로 명확히 합니다. 단순 배율, 반전(100-값), 65535로 나누기 등으로 피부 수분율을 만들어내지 않았습니다. FDC2112 유효 DATA는 하위 12비트입니다.

자동 감지의 최소 2%는 신호 변화 기준이지 완전한 피부 접촉 판정이 아닙니다. 작고 안정적인 변화도 완료될 수 있고, 접촉 면적/압력의 적절성을 이 센서 신호 하나만으로 확인할 수 없습니다. 3%의 원인(실제 작은 신호 변화, 보정 당시 조건, 접촉 면적/위치, 접촉이 완성되기 전 시작 등)은 실제 표본 없이 확정할 수 없습니다.

피부 분석에 측정값 저장/표시는 연결하지만 추천용 수분 점수/건조 판정에는 자동 대입하지 않습니다. 기준 장비와의 짝지은 측정에 근거한 변환식은 아직 없습니다. 이를 연동 오류와 구분해야 합니다.

다음 확인 자료: 완료 화면의 '이번 측정 실험 데이터 내려받기' JSON. 가능하면 공기 중 보정 후 같은 왼쪽 뺨 위치에서 반복 측정 3회를 각각 내려받으세요. 이 파일로 기준값, 표본 분포, 시간, 변화량을 검토할 수 있습니다.
