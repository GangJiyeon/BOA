# 피부 수분 상태 추정기 — 실험 모델

모델: `hydration-estimate-pnj-2023-v1`

## 무엇을 구현했는가

한 번 피부에 접촉하면 고정 3초 동안 수집하고 종료한다. 마지막 1초의 중앙값으로 공개 Moisture click 예제에 대응하는 신호 지수를 계산한다. 이 지수로 상태를 먼저 추정한 다음, 표시 점수와 기존 추천 카테고리를 정한다. 정전용량 증가율 10%를 임의로 100점으로 늘려 상태를 정하던 경로는 신규 판정에 사용하지 않는다.

이 모델은 공개 코드에서 차용한 **미검증 실험 추정기**다. 보드의 정전용량 반응을 피부 수분 함량으로 교정하거나, BOA의 부족·보통·충분 분류 정확도를 입증한 모델은 아니다. 공개 구간을 채택한 것은 BOA의 실험 설계 결정이며 정확도 개선의 실측 증거가 아니다. 접촉 압력·면적·화장품·접지의 영향을 분리하지 못한다. 압력을 올려 정상 점수를 만들도록 안내하지 않는다.

## 판정 기준

PNJ 2023의 동일 보드 연구 공개 부록은 제조사 정수 출력에 6개 상태 구간을 적용한다. BOA에서는 그중 Very Low·Low를 부족, Low Normal·Mid Normal·High Normal을 보통, Very High를 충분으로 합치는 실험 정책을 채택했다. ‘충분’이라는 한국어 상태의 적합성 자체가 별도로 검증된 것은 아니다.

| 공개 예제 기준의 정수 신호 지수 | BOA 추정 상태 | 기존 추천 카테고리 | 화면 점수 구간 |
|---|---|---|---|
| 0–22 | 부족 | 개선 필요 | 1–33 |
| 23–45 | 보통 | 보통 | 34–66 |
| 46–100 | 충분 | 양호 | 67–100 |

점수 구간은 기존 UI·추천 API 표현 규약이다. 피부 수분의 경계값 근거가 아니다. 각 상태가 정해진 뒤 해당 구간 안에서 지수에 따라 단조 증가하도록 표시한다. 따라서 추천 시스템이 기존 점수 구간을 다시 읽어도 처음 추정한 상태와 일치한다. 서버는 점수에서 상태를 역으로 만들지 않고 추정 상태에 해당하는 DB 카테고리를 직접 선택한 뒤 점수의 포함 여부를 검증한다.

## 센서 설정과 계산

현재 센서는 gain16, offset170, 입력 주파수 분주비 FIN2를 유지하고 reference divider를 44·22·11 중에서 선택한다. 공기 raw 값으로 선택된 divider를 추측하지 않는다. 새 펌웨어는 검증된 설정을 BLE v4 패킷에 전송하고, 실제 측정 결과에도 그 설정을 저장한다. 알 수 없는 설정·다른 gain/offset/FIN 또는 측정 중 설정 변경은 새 추정에 사용하지 않는다.

구형 제조사 드라이버는 `x10` 인자를 그대로 쓰지 않고 CLOCK_DIVIDERS에 `0x2001 | clk_div`를 기록한다. 그러므로 x10 인자(0x000A)의 실제 reference divider는 **11**이다. BOA는 이 확인 가능한 구형 제조사 동작을 계산 기준으로 선택했다. PNJ가 사용한 Arduino 포트의 내부 구현은 확인되지 않았으므로, 그 실험 설정을 완전히 재현했다고 주장하지 않는다. 앞선 검토 문서의 명목 divider10 계산은 이번 모델에 사용하지 않는다.

공기 기준 B, 마지막 1초 중앙값 x, 장치가 전송한 실제 divider D에 대해:

```
B_ref = (B + 170) × 11 / D − 170
x_ref = (x + 170) × 11 / D − 170
response = 100 × (B_ref − x_ref) / B_ref
index = floor(response)
```

index로 위 표의 상태를 선택한다. 부동소수점 경계 오차만 막기 위해 floor 전에 1e-9를 더한다. B_ref가 양수가 아니거나 x_ref가 음수이면 공개 예제 표현 범위를 벗어나므로 상태를 만들지 않는다. 오류·표본 누락·접촉 해제도 허구의 결과로 채우지 않는다. 조건을 만족한 정상 접촉의 측정 시간을 연장하거나 재접촉을 자동 요구하지 않는다.

이 환산은 같은 내부 clock에서 reference divider 변경을 보정하는 전기적 계산이다. 내부 clock의 보드 간 편차, 전극 접촉 차이, 피부 부위 차이를 보정하는 생체 교정식은 아니다. 예제의 짧은 평균을 BOA의 고정 3초 중 마지막 1초 중앙값으로 바꾼 것도 실험적 적용 차이다.

## 추천 연결과 데이터

서버가 원시 표본과 sensor_profile로 상태를 다시 계산한다. 클라이언트가 계산한 점수·상태를 제출받아 신뢰하는 API는 추가하지 않았다. 결과에는 estimated_state, estimation_version, estimation_basis, validation_level과 신호 지수를 보존한다. validation_level은 `experimental_unvalidated`, scoring_status는 `experimental_estimate`다. calibrated_score는 계속 null이며 임상 교정으로 표시하지 않는다.

부족 추정은 앞서 적용한 보습·수분 손실 억제 정책으로, 보통·충분 추정은 유지 관리 정책으로 연결한다. 선택적 향료·에탄올·변성알코올 제외는 부족 추정과 사용자의 옵션 선택이 모두 있을 때만 적용된다. 충분을 지성으로 취급하지 않는다. 이 추천은 실험 추정을 입력으로 사용하는 것이며, 개인별 효능을 검증한 결과가 아니다.

기존 engineering normalization 결과는 조회 호환성을 유지한다. 구형 형식으로 새 결과를 제출해도 그 임의 점수를 새 피부 상태로 분류하거나 SkinScore에 저장하지 않는다. 이미 저장된 과거 기록을 새로운 모델로 몰래 재계산하거나 삭제하지 않는다. 새 측정은 해당 분석의 수분 점수 한 개를 갱신한다.

## 검증 범위

- 공개 정수 구간 경계 22.999/23 및 45.999/46, 낮음·정상·높음 신호, 등가 divider11·22·44 변환 일관성 시험.
- 설정 누락·미검증·지원하지 않는 설정 거부, 측정 중 설정 변경 거부, BLE 오류 비트와 설정 비트 분리 시험.
- 세 상태 각각 실제 측정 저장 API → 분석 조회 → 추천 정책 상태 및 선택적 제외 연동 시험.
- 기존 점수 경로의 신규 상태 생성 차단, 중복 저장·명시적 재측정 갱신 시험.
- 고정 3초 타이머·패킷 종료, 반복 접촉에도 완료 한 번, 데이터 끊김·재시작·카운터 wrap 시험.
- 실제 과거 기록의 소프트웨어 재생 시험: B2540, 대표값2506을 D44로 **가정**하면 기준 지수1, 부족 추정, 표시3점. 과거 기록에 실제 divider 정보가 없으므로 이를 장치 설정 확인이나 실제 피부 상태의 정답 검증으로 사용하지 않는다.
- 프론트 production 빌드와 DOM을 통한 측정·사진 분석·추천 갱신 시험, 펌웨어 C++ 호스트 모형 시험.

이번 환경에서 새 펌웨어의 UNO R4 타깃 빌드와 실제 장치 측정은 수행하지 않았다. 소프트웨어 시험 통과는 피부 판정 정확도 시험 통과를 뜻하지 않는다.
