# 회원 연동 1단계 — 분석 결과 소유자와 접근 제한

2026-11-14. 로컬 변경이며 배포·운영 DB 변경은 수행하지 않았다.

## 문제와 변경

프론트는 이미 HttpOnly 인증 쿠키를 API에 전송하지만, 피부·헤어 서버는 그 쿠키를 분석 결과 소유자 저장에 사용하지 않았다. 지금은 아래처럼 처리한다.

1. 피부 JSON·사진 분석, 헤어 랜드마크·사진 분석·추천에서 `require_analysis_actor`로 촬영 동의 또는 회원 상태를 확인한다.
2. 소유자는 body/Form의 임의 번호 대신 서버가 판별한 actor에서 가져온다. 기존 JSON 필드는 호환용으로 남겨도 저장에는 사용하지 않는다.
3. 피부·얼굴형·헤어 추천 조회와 기존 얼굴형을 이용한 추천에 소유권 검사를 적용한다. 타인 결과와 없는 결과는 404로 처리한다.
4. 결과가 회원에게 이관됐다면 회원 소유권을 우선한다. 이전 guest_id가 결과에 남아 있어도 비회원은 읽지 못한다.
5. 수분 측정 연결·저장 및 같은 측정 ID 재시도에도 소유자를 검사한다.
6. 분석 전 비회원 quota를 검사한다. 헤어는 기존 HairRecRun 집계 정책을 유지한다. 얼굴형과 추천을 각각 차감하지 않는다.
7. get_actor에서 JWT뿐 아니라 실제 회원 존재도 검사해 탈퇴 후 남은 토큰을 거절한다.

회원 존재 조회를 추가했으므로 초기 문서의 “액세스 인증은 DB 조회 없음”과 달라졌다. 현재는 삭제된 계정의 접근을 차단하는 쪽을 선택했다.

## 프론트 호환

사진 업로드 경로와 성공 응답 형식은 유지했다. 결과 조회 시 없는 결과와 타인 결과는 동일한 404 본문을 반환한다. 프론트 연결 상태 영역의 오래된 “세션별 저장과 사용 횟수 연결 준비 중” 문구는 제거했다. 프론트의 analyzeSkinPhoto·analyzeFace·recommendHair는 소유자 번호 없이 그대로 호출할 수 있다. 먼저 계정 화면에서 로그인하거나 촬영 동의 후 비회원 이용을 시작해야 한다.

과거 소유자 없는 결과는 자동 이관하지 않는다. 직접 분석 API를 호출하던 스크립트도 이제 인증 쿠키 또는 유효한 비회원 세션이 필요하다. QR 공개 조회는 기존 토큰 기반 흐름을 유지했다.

## 검증

- 새 회귀 테스트 `backend/tests/test_analysis_ownership.py`: 10개 통과.
- CV·랜드마크 계산만 대역 처리하고 FastAPI 요청·SQLite 저장·조회·quota·이관은 실제 코드 실행.
- 회원·비회원 소유자 저장, 다른 회원 조회/재사용 거절, 이전 guest의 이관 결과 접근 거절, 익명·세션 없는 키오스크 거절, 피부·헤어·IP 제한, 회원·키오스크 제한 면제, 수분 저장·재시도 소유권, 삭제 회원 JWT 거절을 확인.
- 기존 추천·수분 테스트 공통 fixture는 고정 회원 actor를 명시하도록 변경. 실제 인증 가드는 새 테스트에서 별도로 검증한다.
- 전체 테스트 실행 당시 294개 중 293개 통과. `test_hair_studio.StyleRefTest.test_masks_reference_face_gray` 1개는 실행 환경의 MediaPipe NSOpenGLPixelFormat 생성 실패로 오류. 해당 이미지/CV 코드는 이번 단계에서 수정하지 않았다.
- 이후 추가한 테스트 3개를 포함한 새 회귀 테스트 10개는 별도 실행으로 모두 통과했다.
- 실제 Google·SMTP·운영 PostgreSQL·브라우저 실사용 검증은 수행하지 않았다.
