# 피부 수분 측정: 원시 신호 취득 개선

대상은 Arduino UNO R4 WiFi + FDC2112 Moisture click, Qwiic/Wire1 연결이다. 추가 장비나 분리 접촉 3회를 요구하지 않는다. 한 번 접촉 안에서 안정화하고 3초 창을 평가하며, 완료 또는 실패 후에는 명시적으로 다시 측정을 선택해야 한다.

## 이번에 해결한 범위

기존 로그의 공기 508, 접촉 504는 차이가 4 counts뿐이었다. 표시 백분율을 크게 만드는 것으로 이 원시값의 분해능을 개선할 수는 없다. 이번 변경은 FDC2112의 기준 클록 분주비를 조정해 같은 센서 주파수 변화가 더 많은 출력 단계에 걸쳐 나타나도록 한다.

- 초기화 때 gain=1, offset=0으로 8개 새 변환을 읽는다. 설정값을 실제 레지스터에서 읽어 검증한 뒤에만 이 결과를 사용한다.
- 기준 분주비 44 → 22 → 11 순으로, gain=16 전환 후 출력 범위를 안전하게 사용할 수 있는 첫 설정을 선택한다. 해당 프로파일이 모두 범위를 벗어나거나 변환 경고·통신 오류가 있으면 초기화에 실패한다.
- gain=1 출력에 숨겨진 4비트의 모든 가능성을 포함해 범위를 검사한다. 최종 출력은 여유 범위 64~3584 안에 있어야 한다. 이는 공학적 범위 정책이며 피부 상태 판정 경계가 아니다.
- gain=16, offset=170, FIN=2는 유지한다. 선택한 분주비는 재초기화 전까지 바꾸지 않으며 공기 기준은 새로 취득한다. 기존 보정값과 서로 다른 설정의 원시값을 섞지 않는다.
- 센서 설정을 바꿀 때는 sleep에 진입하고 이전 unread 변환을 지운다. 모든 설정의 readback을 확인한 뒤 작동시킨다.
- 범위를 확인하는 동안에는 33 MHz deglitch 필터를 사용한다. 선택 가능한 최종 프로파일의 최대 주파수는 내부 클록 최대 55 MHz를 적용해도 약 572 kHz 미만이므로, 실제 측정에는 TI 권고대로 그 위의 가장 낮은 대역인 1 MHz를 선택한다.
- RCOUNT=4096, SETTLECOUNT=256. 분주비44, 내부 클록 최저35 MHz에서도 변환과 안정화 시간의 합은 약87.6 ms로 100 ms 발행 주기보다 짧다. 실제 새 변환 여부는 계속 확인한다.
- 공기 보정의 허용 변동량은 분주비에 맞춰 조절한다. 종전 30-count 비교값은 펌웨어 시리얼 출력에서 제거했다.

## 계산과 기대 효과

TI 데이터시트 식8에 따라 이 설정의 주파수는 다음과 같다.

`f_sensor = 2 × (f_CLK / D) × (raw + 170) / 65536`

같은 센서 주파수와 같은 내부 클록을 가정하면 D=11 →44에서 다음 관계가 성립한다.

`raw_new = 4 × (raw_old + 170) − 170`

| 항목 | 기존 설정 예시 | 새 설정의 이론적 대응값 |
|---|---:|---:|
| 공기 기준 | 508 | 2542 |
| 접촉값 | 504 | 2526 |
| 원시값 차이 | 4 | 16 |
| 기존 정전용량 반응률 | 1.17646% | 1.17646% |
| 출력 한 단계의 반응률 변화 | 약0.2933%p | 약0.0733%p |

이 표의 새 설정 값은 실제 측정값이 아닌 이론적·합성 입력이다. 실제 피부에서 4배 정확해졌다는 의미가 아니다. 내부 클록 잡음, 손·몸의 전기적 결합, 접촉 면적과 힘, 표면 상태에 따른 오차는 별도로 남는다. 초기 측정 범위에 따라 분주비22 또는11을 선택할 수도 있다.

프론트엔드와 백엔드의 현재 비율 계산은 동일한 설정 안에서의 공기/접촉 주파수 비율을 사용하므로 분주비가 소거된다. 새 설정에서도 비율의 뜻은 유지된다. 과거 원시값을 단순히 4배 해서 실제 측정 자료로 취급하지 않는다.

## 실제 적용

1. ZIP의 파일들을 현재 BOA 프로젝트 루트에 덮어쓴다. 현재 사용 중인 피부 측정/분석 연동 프로젝트에 적용하는 업데이트다. 프로젝트 전체를 새로 설치하는 ZIP은 아니다.
2. Arduino IDE에서 `hardware/arduino/moisture_sensor/moisture_sensor.ino`를 연다. 같은 폴더의 `Fdc2112.h`, `MoistureBle.h`까지 세 파일이 함께 있어야 한다. 보드 UNO R4 WiFi, 해당 COM 포트를 선택하고 업로드 버튼을 한 번 누른다. 탭마다 업로드하지 않는다.
3. 시리얼 모니터115200에서 `BOA firmware: moisture-acquisition-v12`, `ACQUISITION ... headroom_ok=1`, `CONFIG verified=1`을 확인한다. 로그는 선택한 분주비를 포함한다. 기존과 같은 신호라면 분주비44를 예상하지만 이를 보장하지 않는다. 시리얼 모니터는 확인 후 닫는다.
4. 백엔드를 재시작하고 프론트엔드를 다시 켠다. 브라우저를 새로고침해 센서를 재연결한다.
5. 센서 면을 손·피부에서 떼고 웹의 기준값 보정을 실행한다. 준비 후 피부의 같은 위치에 가볍게 한 번 접촉하고 안내에 따라 유지한다. 숫자를 높이려고 더 세게 누르지 않는다. 종료 후 이번 측정 실험 데이터와 전체 측정 로그를 내려받는다.

Windows의 기존 프로젝트 경로 기준:

```powershell
cd C:\Users\USER\Desktop\BOA-git\backend
docker compose restart api
```

별도 터미널:

```powershell
cd C:\Users\USER\Desktop\BOA-git\frontend
npm run dev
```

서버 소스를 이미지에 복사해서 실행하는 환경이라면 재시작 대신 `docker compose up -d --build api`를 사용한다.

## 검증한 것과 남은 것

- 실제 UNO R4 WiFi 타깃 컴파일 통과: Arduino UNO R4 Boards1.6.0 / ArduinoBLE2.1.0. USB 업로드와 실제 센서 작동은 이 환경에서 수행할 수 없었다.
- 실제 ino를 포함한 C++ 테스트: 프로파일 선택과 fallback, 상·하한, gain 설정 실패, 경고, 변환 미수신, 재접속, 보정 및 BLE 데이터 처리.
- 프론트엔드: 같은 물리 반응에 해당하는 합성 입력에서 백분율 불변·출력 단계 감소·단일 완료 확인. 기존 실제 로그의 실패 처리 회귀 확인. DOM 연동 및 production build 통과.
- 백엔드44개 테스트 통과. 새 원시값 범위의 서버 검증, 재계산, 기존 저장·추천 전달 경로를 확인했다.

실제 장치에서 공기 잡음과 접촉 신호가 개선됐는지는 새 로그로 확인해야 한다. 이 단계의 숫자는 정전용량 반응률이다. 검증된 피부 수분 함량 백분율이나 Corneometer AU로 환산하는 보정 모델은 확보하지 못했다. 현재 추천 연결은 실험적 보조 반영이며, 임상적 건조 판정이나 보정된 수분 점수로 반영되는 것은 아니다. 따라서 피부 수분 측정 전체를 검증 완료했다고 주장하지 않는다.
