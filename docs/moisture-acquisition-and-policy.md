# 수분 측정: 수집 오류 처리와 판정·표시 분리

## 이번 작업의 완료 범위

1회 피부 접촉·고정3초·완료1회를 유지하면서 정상 변환 대기를 즉시 실패로 처리하던 부분과 표시 점수가 추천 상태를 다시 결정하던 연결을 수정했다. **이번 소프트웨어 수정으로 실제 피부 건조 판정 정확도가 검증된 것은 아니다.**

## 수집

- `not_ready`는 새 변환이 아직 없는 상태다. 해당 패킷을 측정값으로 만들지 않고 다음 새 표본을 기다린다.
- 초반의 일시적 오류 표본은 제외한다. 시간은 추가하지 않는다. 기존 조건인 정상 표본 최소25개, 정상 표본 사이 최대350ms, 마지막 표본이 고정 창의 최소2650ms까지 도달해야 한다는 조건을 유지한다.
- 대표값을 구하는 마지막1초에 sensor_error가 있으면 판정하지 않는다. 강한 접촉에서 오류가 난 값만 제외하고 약한 반응으로 건조 판정을 만드는 선택 편향을 막기 위한 수집 유효성 조건이다. `not_ready`는 그 자체로 이 sensor_error 조건에 해당하지 않는다.
- 제외된 패킷은 정상 샘플과 별도로 discarded_samples에 순번·장치 시각·상태·경고 비트·진단 raw를 저장한다. 이 값들은 대표값·평균 계산에 넣지 않는다. 서버도 중복·시간 범위·경고 비트·마지막 구간 오류를 검증한다.
- 정상 측정 상세에 정상 표본 수와 제외·경고 수를 표시한다. 실패 시 기존 ‘전체 기록 내려받기’에 실패 전 수신 데이터가 남는다. 실패 후 자동 재접촉 측정을 시작하지 않는다.

## 펌웨어

부팅 문구는 `BOA firmware: moisture-acquisition-v14`다. 기존 Wire1·Qwiic·BLE v4와 읽기 설정을 사용한다. 진폭/타임아웃 경고가 있는 데이터도 진단 raw는 전송하되 status는 오류로 유지한다. STATUS에 경고 방향이 실제로 기록됐을 때만 amplitude_low/high로 구분한다. 방향을 알 수 없는 경우 amplitude_warning으로 기록한다.

TI 데이터시트는 LC 진폭을 지정 범위에 맞춰 IDRIVE를 정하도록 설명한다. 현재 사용자 장치의 경고 원인이 어느 방향인지 확인되지 않아 경고를 끄거나 구동 전류를 임의로 올리는 수정은 하지 않았다. 지속적인 진폭 경고의 원인을 해결했다고 보고하지 않는다.

## 판정 → 추천 → 표시

- 실험 상태 분류와 표시 점수 함수를 분리했다. 실제 피부 기준과의 대응이 확인되지 않은 기존 공개 코드 차용 구간을 새 검증 기준으로 승격하거나 낮은 숫자를 높이는 환산을 넣지 않았다.
- 추천 요청에 분석 ID와 측정 ID를 함께 전달한다. 서버는 두 ID에 연결된 저장 표본과 설정을 읽어 같은 버전의 실험 상태를 다시 계산한다. 요청에 적힌 화면 점수와 카테고리로 센서 판정을 덮어쓰지 않는다.
- 센서 상태를 사용하는 추천에서는 카테고리를 직접 적용한다. 표시 점수가 DB의 과거 구간 밖으로 바뀌어도 이를 이유로 다른 센서 상태를 만들지 않는다.
- 같은 저장 측정에 클라이언트 점수를1·50·100, 라벨을 서로 다르게 보내도 추천·제외·페이지 토큰이 동일함을 시험했다. 서버의 표시 함수만90점으로 바꾼 시험에서도 상태와 추천 제품은 같았다.
- 응답 hydration_policy.basis는 persisted_sensor_estimate다. 기존 수동 입력은 기존 점수 계약을 유지한다. 실험 추정의 validation_level은 experimental_unvalidated로 유지한다.

## 확인한 것과 확인하지 못한 것

백엔드54개 시험, BLE 프로토콜·고정3초 자동 측정 시험, 측정→사진 분석→저장된 판정 기반 추천 DOM 시험, production 빌드, 펌웨어 C++ 호스트 시험을 수행했다. 실제 사용자 장치와 UNO R4 타깃 빌드는 이 환경에서 실행하지 않았다. 과거 raw 재생만으로 사용자의 실제 피부 상태 정답을 확인할 수 없다.

현재 남은 핵심 문제는 실제 피부 건조 상태와 센서 반응의 대응이다. 정상 데이터 수집 성공, 코드 실행 성공, 점수 일관성 시험 성공은 그 대응의 검증을 대체하지 않는다. 따라서 낮은 표시 점수만으로 사용자가 심한 건성이라고 결론내리지 않는다.

센서 중단 원인을 확인하려면 업데이트 후 한 번의 정상 접촉 시도에서 ‘측정 데이터’ 또는 실패 시 ‘전체 기록’을 사용한다. 이 기록으로 오류 비트·누락·정상 표본을 확인할 수 있지만, 그 기록 하나가 피부 수분의 기준 정답이 되는 것은 아니다.
