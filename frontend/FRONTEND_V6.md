# 프론트 v6 — 이번 분석 결과

프론트 v5 및 화장품 일상 관리 패치가 적용된 상태에 추가하는 프론트 전용 변경이다.
백엔드·DB·마이그레이션·API 계약·팀원 추천 알고리즘은 변경하지 않는다.

## 사용 흐름

- 메뉴 ‘결과 확인’을 ‘이번 분석 결과’로 변경한다.
- 피부·화장품 및 헤어 화면에서 마지막으로 완료한 결과를 모아 표시한다.
- 피부 점수, 화장품 함유 성분과 근거, 얼굴형·차순위 얼굴형 및 헤어 추천을 표시한다.
- 각 결과의 입력·추천 조건 변경은 기존 피부/헤어 화면으로 돌아가서 진행한다.
- 완료한 제품 종류 필터와 더보기 결과도 모아보기 화면에 반영한다.
- 일상 관리 제안과 개선 목적 성분 매칭의 표현을 기존 화면과 동일하게 유지한다.
- 사진 분석, JSON 연동 확인, 개발용 가정 점수를 구분하며 테스트 입력에 과거 피부 분석 ID를 붙이지 않는다.
- 새 피부 분석이 완료되면 이전 화장품 추천을 제거한다. 새 추천이 실패해도 이전 제품이 새 점수와 섞이지 않는다.
- 입력 편집 중에는 마지막 완료 결과가 남는다. 새 추천 완료 후 해당 항목을 대체한다.
- 제품이 0개인 완료 결과도 사유와 함께 표시한다.

## 저장 및 조회 범위

이번 이용 중 프론트 메모리에 보관하는 결과다. 새로고침 후 자동 복원이나 계정별 과거 기록 조회를 구현한 것이 아니다.
새 비회원/키오스크 이용 시작, 로그인 성공, 로그아웃, 회원가입, 키오스크 이용 종료 시 결과와 입력 화면 상태를 초기화한다.
로그인 실패 시에는 기존 결과를 유지한다.
유효한 비회원 세션의 ‘세션 이어서 시작’은 결과와 사진·입력 조건을 유지한다.
기존 GET `/api/actor`로 세션 상태를 확인하고, 유효한 비회원이면 세션 생성 API를 다시 호출하지 않는다.
세션이 만료됐으면 동의 항목을 다시 표시하며, 동의 후 새 이용을 시작할 때 기존 결과를 초기화한다.
모아보기 진입만으로 분석·추천을 다시 호출하지 않는다.

일반 화면의 QR 토큰 입력·공유 링크 복사·계정 이관 버튼을 제거한다.
기존 `#/results?token=...` 주소는 공유 조회 준비 중이라는 안내와 현재 화면의 결과만 표시하며 QR API를 호출하지 않는다.
기존 백엔드 QR API와 프론트 API 클라이언트는 그대로 둔다.

분석 번호 조회는 접힌 ‘개발용 도구’ 안으로 분리한다.
기존 피부/헤어 GET API만 사용하며 조회한 결과는 이번 결과 목록에 추가하지 않는다.
도구 닫기·입력 변경·페이지 이탈 시 진행 중인 조회를 취소한다.

## 적용 (PowerShell)

BOA-git 루트에서 다운로드 경로를 확인하고 적용한다.

```powershell
$patch = "$env:USERPROFILE\Downloads\boa-frontend-results-v6.patch"
git apply --check $patch
if ($LASTEXITCODE -ne 0) { throw "패치 확인 실패. 강제로 적용하지 마세요." }
git apply $patch
if ($LASTEXITCODE -ne 0) { throw "패치 적용 실패." }
cd frontend
pnpm build
pnpm lint
node scripts/test-api-client.mjs
```

백엔드 재시작·데이터 가져오기·DB 마이그레이션은 필요 없다.
Vite 개발 서버가 실행 중이면 화면을 새로고침한다. 완료 결과는 초기화되므로 피부/헤어 흐름을 다시 실행한다.
GitHub push/merge는 포함하지 않는다.

## 검증

- TypeScript/Vite 빌드, Oxlint, 기존 API 클라이언트 16개 확인 통과.
- 브라우저에서 31개 확인 통과: 빈 화면, 이전 공유 주소 안내, 별도 번호 조회,
  피부·화장품 전달, 필터/더보기 동기화, 실패 시 완료 결과 유지, 새 분석 점수와
  이전 제품 분리, 결과 페이지를 보는 동안 완료되는 요청, 얼굴형·헤어 동시 표시,
  JSON/가정 점수 구분, 0개 결과 갱신, 새 비회원 세션 및 새로고침 초기화.
- 모바일 390px 가로 넘침 및 브라우저 예외 없음.
- 브라우저 검증의 API 응답은 테스트 대역이다. 실제 사진 분석이나 팀원 DB를 재검증한 것은 아니다.
- 백엔드 파일 변경 0개.

## 검수 후 세션 수정 패치

위 v6 패치를 적용한 상태에서 `boa-frontend-session-fix-v6.patch`를 추가 적용한다.

```powershell
$patch = "$env:USERPROFILE\Downloads\boa-frontend-session-fix-v6.patch"
git apply --check $patch
if ($LASTEXITCODE -ne 0) { throw "패치 확인 실패. 강제로 적용하지 마세요." }
git apply $patch
if ($LASTEXITCODE -ne 0) { throw "패치 적용 실패." }
cd frontend
pnpm build
pnpm lint
node scripts/test-api-client.mjs
```

수정 후 빌드·린트·API 클라이언트 16개와 브라우저 41개 확인 통과.
기본 화면 흐름 31개에 비회원 이어가기, 사진·결과 유지, 세션 생성 호출 방지,
만료 후 재동의 및 새 이용 초기화, 로그인 실패 시 유지, 로그인 성공 시 결과·사진 초기화를 추가 확인했다.
브라우저 확인에는 테스트 API 응답을 사용했다. 백엔드 변경 및 GitHub push/merge는 없다.
