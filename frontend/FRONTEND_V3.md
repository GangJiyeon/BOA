# BOA 프런트엔드 v3

기준 커밋: `11d48ac` (v2 패치 적용 상태).
이번 패치는 `frontend/`만 변경한다. 백엔드 코드, API 계약, 추천 규칙, DB, 마이그레이션을 변경하지 않는다. 패키지 추가나 의존성 변경도 없다.

## 화면 구성

- `#/home`: 피부·헤어 시작 카드, 이번 실행 결과 바로가기, 계정·AI Studio 안내.
- `#/skin`: 사진 드래그앤드롭·선택·미리보기·삭제, 선택 수분값, 제품 종류·성분 제외 조건, 분석 단계, 지표 카드, 성분 매칭 제품과 근거.
- `#/hair`: 사진 1장/3장, 실제 카탈로그의 길이·질감, 얼굴형 결과, 추천 스타일 카드·이미지·설명.
- `#/results`: 이번 실행 결과, 저장된 번호 조회, 세션 링크 복사·조회·계정 이관.
- `#/start`: 비회원 동의, 이메일 인증·가입, 회원 언어 설정·갱신·로그아웃.
- `#/kiosk`: 관리자 등록·해제, 사용자 시작·종료.
- `#/studio`: API 연결 준비 상태.

첫 접속은 홈이다. 상단 계정 표시와 메뉴로 로그인 화면에 갈 수 있다. 데스크톱은 왼쪽 메뉴, 모바일은 가로 스크롤 메뉴를 사용한다. 메뉴 변경 시 본문 시작으로 이동하며 피부·헤어의 입력값과 결과는 세션 내에서 유지된다.

개발용 JSON·임시 점수 슬라이더는 피부 화면의 ‘연동 테스트 도구’에 접어 두었다. 기본 흐름은 사진 분석 결과를 받아 추천 요청에 전달하는 방식이다. 서버 점수·등급은 수정하지 않으며 수분 미측정은 0점으로 바꾸지 않는다. 홍조·트러블의 점수 방향도 별도로 표시한다.

## 연결 상태와 제한

사진 분석은 기존 multipart API, 추천은 기존 JSON API를 사용한다. 추천 결과의 추가 조회·동점 그룹·근거 표시를 유지했다. 서버가 추천을 보류하거나 후보가 없다고 응답하면 빈 결과 이유를 그대로 보여 준다.

계정·QR·키오스크 폼은 현재 API를 호출하지만, 분석의 사용자 귀속·사용량 제한·QR 헤어 자동 저장은 현재 백엔드에 남은 작업이다. 이메일 실제 발송, 공식 약관 본문, Google 프런트 인증, AI Studio 생성도 이전과 같이 준비 상태다. 프런트 화면은 이 기능들이 완료됐다고 표시하지 않는다.

사진 드래그앤드롭과 파일 선택은 동일한 검증을 사용한다. JPG/PNG/WEBP만 받으며 피부는 1장, 헤어는 최대 3장이다. 헤어 2장은 분석 제출 시 거부한다. 선택 목록은 파일 입력의 브라우저 값과 별도 상태로 관리해 같은 파일도 다시 선택할 수 있다. 삭제·로그아웃·사용자 종료 시 사진 미리보기 URL을 해제한다.

로컬 주소의 공유 링크는 같은 기기에서만 열 수 있음을 표시한다. 링크 복사는 브라우저 클립보드를 사용할 수 없으면 직접 선택·복사하도록 안내한다.

## 적용

이미 v2를 적용한 작업 폴더에서 실행한다. 패치 확인에 실패하면 실제 적용을 진행하지 않고 작업 폴더의 버전을 확인한다.

```powershell
cd C:\Users\USER\Desktop\BOA-git
git apply --check "$env:USERPROFILE\Downloads\boa-frontend-v3.patch"
git apply "$env:USERPROFILE\Downloads\boa-frontend-v3.patch"
cd frontend
pnpm build
pnpm lint
node scripts/test-api-client.mjs
pnpm dev
```

현재 실행 중인 백엔드를 그대로 사용한다. DB 변경 명령은 필요하지 않다.

## 검증

- TypeScript·Vite 빌드, oxlint, API 클라이언트 16개 검사 통과.
- 브라우저에서 피부·헤어 업로드 → 실제 FastAPI 라우트 → 테스트 SQLite DB 저장·추천 → 점수·카드·이미지 표시 확인.
- CV 분석 함수는 테스트 대역이다. 실제 사진의 인식 정확도는 이 자동 검사에 포함하지 않는다.
- 계정·QR·키오스크는 API 응답 대역으로 요청값·화면 전환·초기화·가입/이관 후 링크 제거·등록 해제를 확인했다. 실제 이메일 수신이나 운영 DB 인증을 완료한 것으로 간주하지 않는다.
- 추천 장애 후 재시도 시 분석 중복 생성 방지, 메뉴 이동 후 입력·결과 유지, 로그아웃 후 초기화 확인.
- 잘못된 사진 형식, 드래그앤드롭·삭제, JSON 입력 오류, 수분 미측정에 따른 실제 빈 추천 응답, 모바일 가로 넘침을 확인했다.
- 화면 검증에는 한글 폰트를 테스트 브라우저에만 주입했다. 애플리케이션은 사용자 기기의 한글 시스템 글꼴을 사용하며 외부 폰트 서비스에 의존하지 않는다.
